# Устройство программы «Ttranslator» (версия 0.9.2)

## Коротко

Три части на одном компьютере, без интернета:

```
окно программы (окно приложения ttranslator-window, запасное — Edge/Chrome --app; или вкладка браузера)  ⇄  программа запуска (Go, 127.0.0.1:8765)  ⇄  движок llama-server (llama.cpp, 127.0.0.1:случайный порт)
        ui/index.html                              Ttranslator.exe / ttranslator-linux           модель .gguf из папки models
                                                                   │
                                                                   └→ sherpa-onnx-offline-tts (на каждую фразу чтения вслух) + голос Piper из models/voices
```

- **Программа запуска** скачивает движок и модели, запускает и останавливает движок, отдаёт интерфейс, передаёт запросы интерфейса движку, хранит сохранённые переводы, словари и отчёты, закрывается вместе с окном.
- **Интерфейс** — один файл `ui/index.html` (HTML + CSS + JavaScript, без внешних ресурсов). Вся логика перевода (запросы к модели, стили, словарь, чат, тест) — здесь.
- **Движок** — `llama-server` из официального выпуска llama.cpp b11435, OpenAI-совместимый `/v1/chat/completions` с потоковой выдачей.
- **Чтение вслух** — программа `sherpa-onnx-offline-tts` из официального выпуска sherpa-onnx v1.13.7 и голоса Piper; скачиваются по требованию (при первом голосе), запускаются на каждую фразу и сразу завершаются.
- **Окно приложения** (с 0.9.1; с 0.9.2 — вид окна по умолчанию, `launch_mode: window`) — программа `ttranslator-window` (C++, библиотека webview): обычное окно с веб-движком системы (WebView2 в Windows, WebKitGTK в Linux) показывает тот же `ui/index.html`; при запуске — на весь экран (`start_maximized`). Устройство — `source/window/README.md`.

## Папка программы

```
Ttranslator.exe, ttranslator-linux   программа запуска (Windows / Linux)
ttranslator-window.exe, ttranslator-window-linux   окно приложения (Windows / Linux)
start.bat, start.sh                запасной запуск без программы запуска (llama-server сам отдаёт ui/)
README.txt                         инструкция для пользователя (CRLF, UTF-8 с BOM)
LICENSE.txt                        лицензия MIT
config.json                        настройки (создаётся при первом запуске)
ui/index.html                      интерфейс
ui/tests.txt                       фразы для кнопки «Тест» (пользовательский файл)
engine/<os>-<arch>/b11435/...      движок; engine.json — путь к llama-server
engine/<os>-<arch>/sherpa-onnx-v1.13.7-…/   программа озвучки; tts.json — путь к ней (в Windows рядом — копия …-utf8.exe)
models/*.gguf                      модели; *.part — недокачанные
models/voices/vits-piper-*/        голоса для чтения вслух (модель .onnx, tokens.txt, espeak-ng-data или у китайского — lexicon.txt и *.fst, MODEL_CARD);
                                   vits-piper-*.download/ — части голоса из частей, пока он скачивается
data/saved/*.tsv                   сохранённые переводы: по файлу на подборку (до 0.5.1 — один data/saved.tsv)
data/glossary/*.tsv                словари терминов
data/reports/test-*.md|json        отчёты теста
data/logs/                         launcher.log, engine.log, engine.prev.log
data/webview/                      окно приложения: в Windows — данные WebView2 (хранилище страницы, кэш), в Linux — значок окна
source/                            исходный код, документация, тесты
```

Пользовательские данные — `config.json`, `data/`, `models/`, `engine/`, `ui/tests.txt` — при обновлении программы не трогаются.

**Архивы выпуска** (`source/release.sh`, с 0.9.4 — пробные сборки; публикация — только после «да» автора): `Ttranslator-<версия>-windows-x64.zip` и `Ttranslator-<версия>-linux-x64.tar.gz` — одна папка `Ttranslator/` с программами, `ui/`, `README.txt`, `README.md`, `LICENSE.txt`, `THIRD-PARTY.txt` (тексты лицензий llama.cpp, webview и заголовка WebView2 SDK; что скачивается отдельно), `start.bat` или `start.sh`, `source/` и движком, уже распакованным так же, как его распаковывает программа: `engine/<os>-amd64/b11435/…` и `engine.json` (поэтому при первом запуске скачивается только модель). Пользовательских данных и sherpa-onnx в архивах нет. Какие архивы движка класть — `enginePackageFor(goos, goarch)` в `main.go` (тот же размер и SHA-256, что при скачивании), скрипт берёт их через тест `TestDumpReleaseInfo` (`TDOC_DUMP_RELEASE=файл`). Рядом — `SHA256SUMS.txt`.

При переименовании в версии 0.5 оставлены прежними: признак программы `tdoc-translator` (`appID` в `main.go`, по нему вторая копия находит первую), префикс `tdoc.` в хранилище браузера (иначе потеряются выбранные языки и стили), переменные окружения `TDOC_*` и папка `Tdoc`. Старый `Translator.exe` и новый `Ttranslator.exe` занимают один порт и один признак, поэтому одновременно работать не могут.

## Программа запуска (`source/launcher`)

Go, только стандартная библиотека. Файлы: `main.go` (почти всё), `glossary.go` (словари), `saved.go` (сохранённые переводы), `tts.go` (чтение вслух: голоса, программа озвучки, `/api/tts`), `window.go` (окно приложения), `i18n.go` (сообщения на языке интерфейса), `sys_windows.go` / `sys_linux.go` (окно, процессы, сведения о компьютере), `*_test.go`; `rsrc_windows_amd64.syso` — значок Ttranslator.exe (его сам берёт `go build` для Windows), `make_icon.go` — рисует этот значок (в сборку не входит) и `Ttranslator.png` (значок своего окна в Linux, встроен в программу запуска).

**Запуск.** Папка программы — папка исполняемого файла (`TDOC_ROOT` переопределяет). Журнал `data/logs/launcher.log` дописывается (вторая копия программы его не обрезает). Если порт 8765 занят этой же программой (`/api/ping`), вторая копия только открывает окно первой и выходит. Окно открывает `openUI(url, second)`: `launch_mode: window` — окно приложения (`startOwnWindow`, см. ниже), если не вышло — Edge или Chrome с `--app=URL` (`openWindow(url, tab, maximized)`, `appWindowArgs`: `--start-maximized` или `--window-size=1180,780`), а если их нет или выбрано `launch_mode: tab` — браузер по умолчанию. До 0.9.2 окно Edge/Chrome было отдельным выбором `launch_mode: app`; теперь такое значение в `config.json` читается как `window` (`normSettings`). Если `load_model_at_start` выключено, движок при запуске не запускается: флаги `unloaded` и `noModelAtStart` (в `/api/state` — `phase: unloaded`, `no_model_at_start: true`).

**Начало работы.** Флаг `startDone` (`start_done` в `/api/state`) — «запуск закончен»: окно приветствия закрыто (`/api/start-done`) или пользователь загрузил, выгрузил, сменил модель, начал скачивание. Пока он не установлен, окно приветствия по «Начать работу» применяет галочку «Загружать выбранную модель при запуске» к этому запуску (загрузить — `/api/load`, выгрузить — `/api/unload` с `{"at_start": true}`: тогда `no_model_at_start` остаётся и плашка пишет «Модель не загружена.»). Второе окно и окно приветствия, открытое из «Настроек», модель не трогают.

**Жизненный цикл.** Каждое окно держит открытым поток событий `/api/events?page=<номер окна>`. При закрытии или перезагрузке окно отправляет `/api/closing?page=…` (событие pagehide, `navigator.sendBeacon`): с этого момента оно не считается открытым, даже если его соединение почему-то не закрылось. Если открытых окон нет 5 секунд после такого сообщения (20 секунд, если соединение просто оборвалось), программа останавливает движок — память модели освобождается — и выходит; через 10 минут, если окно так и не открылось; пока идёт скачивание — не выходит. Перезагрузка окна (новое окно открывает поток за доли секунды) и второе окно выхода не вызывают. Windows: движок привязан к Job Object и не переживёт программу запуска.

**Окно приложения** (`window.go`). `startOwnWindow` запускает `ttranslator-window(.exe|-linux)` из папки программы: `URL --title Ttranslator --size 1180x780 --data data/webview` (+ в Linux `--icon data/webview/ttranslator.png`, + `--maximized`, если `start_maximized`) и ждёт строку `ready` в stdout (до 30 с). stdout и stderr — свои каналы `os.Pipe`, а не буферы: дочерние процессы веб-движка могут держать stderr открытым, а `cmd.Wait` не должен их ждать. Если программа завершилась раньше: код 3 — «нет веб-движка системы», 127 — не хватает библиотек (Linux), иначе — код и последняя строка stderr; причина попадает в `window.error` в `/api/state`, а открывается окно Edge/Chrome. В Windows программа окна привязана к Job Object (закроется вместе с программой запуска); запущенная второй копией программы (`second`) не привязывается и не запоминается. Сразу после запуска программа запуска отдаёт ей право выйти на передний план (`allowForeground` → `AllowSetForegroundWindow(pid)`; перед окном Edge/Chrome и вкладкой браузера — `ASFW_ANY`): Windows не даёт программе, запущенной фоновой программой, вывести окно вперёд, и окно открывалось за окном папки. Программа окна выводит окно вперёд сама (`bring_to_front`: `SetForegroundWindow`; если отказано, а впереди окно Проводника, — `AttachThreadInput` на мгновение; в Linux — `gtk_window_present`). Страница своего окна открывает поток событий с `ttw=1` (`ownPages`, `window.pages` в `/api/state`). Когда программа окна завершилась (окно закрыли), страница не успевает сказать «закрываюсь», поэтому программа запуска выходит через `byeGrace` (5 с), а не через 20 с (`windowGone`). При выходе (`closeOwnWindow`) окну даётся 2 с закрыться самому (после «Выход» страница вызывает `ttwClose()`), потом программа окна останавливается.

**Ответ при неготовой модели.** Пока движок не готов, запросы интерфейса к `/v1/...`, `/health`, `/props` получают 503: «Please load a model.» (модель выгружена, не запущена или ошибка; текст задан автором, всегда по-английски) или «Модель ещё загружается, подождите.». Интерфейс показывает первое как есть (`NEED_MODEL_MSG`), без приставки «Ошибка движка:».

**Движок.** Параметры: `-m <модель> --host 127.0.0.1 --port <свободный> -c <ctx_size> -np 1 --no-ui --jinja -cram 256 -rea off --api-key <случайный ключ>` (+ `-t` при threads > 0, + `extra_engine_args`). Состояния: stopped, starting, ready, error; флаг `unloaded` — пользователь выгрузил модель, сам движок не запускается. Готовность — `/health`; сведения — `/props` (сборка, контекст).

**Скачивание.** Движок — с github.com, модели — с huggingface.co по ссылкам, закреплённым на конкретный коммит репозитория; размер и SHA-256 проверяются. Файл качается в `*.part` с докачкой (Range); 60 секунд без данных — обрыв. Архив движка распаковывается с защитой от выхода за пределы папки.

**Чтение вслух** (`tts.go`). Каталог голосов `voiceSpecs`: `ID, Lang, Name, Gender, License, NC, Dir, Model, SID, URL, Page, Size, SHA256` (+ `Lexicon`, `Rules`, `Parts`) — архивы голосов Piper в упаковке sherpa-onnx (`github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/vits-piper-<голос>.tar.bz2`: папка с моделью, `tokens.txt`, `espeak-ng-data`, `MODEL_CARD`). Китайский голос (`lexiconVoice`) читает без espeak-ng: в его архиве словарь произношения `lexicon.txt` и правила для чисел, дат и телефонов (`phone.fst`, `date.fst`, `number.fst`); `ttsArgs` передаёт их (`--vits-lexicon`, `--tts-rule-fsts`) вместо `--vits-data-dir`. Голос модели с несколькими дикторами — `speaker(piperVoice(...), sid)`: испанский Sharvard — диктор F (`SID` 1) модели `es_ES-sharvard-medium` (диктор M — 0), `ttsArgs` передаёт `--sid`. Голос, которого нет среди архивов выпуска, — «из частей» (`partsVoice`, `Parts []VoicePart{URL, File, Size, SHA256}`): модель и `tokens.txt` отдельными файлами (например, с Hugging Face автора sherpa-onnx, закреплены на коммит) и `espeak-ng-data.tar.bz2` из выпуска (`espeakPart`); `Size` — сумма частей. Так в 0.9.3 скачивался испанский `es_ES-mls_9972-low`; в 0.9.4 его в каталоге нет (короткие фразы он читал выдуманными словами и в 2–5 раз дольше — изъян самой модели), сейчас голосов из частей в каталоге нет, но механизм и его проверки остаются. Части скачиваются по очереди в `models/voices/<Dir>.download/` (`partPath`; готовая часть — файл без `.part` — не скачивается снова, недокачанная докачивается), ход скачивания — общий (`Done` и `Total` по всем частям), потом файлы переносятся в папку голоса, а архив распаковывается в неё; `voicePartial` — сколько уже скачано (для «скачано N %»), `removeVoiceDownloads` — убрать недокачанное. У голосов в `/api/state` — `parts` (адрес, файл, размер каждой части; у архива — одна часть). Программа озвучки — общий (shared) архив выпуска sherpa-onnx v1.13.7 для своей платформы (`currentTTSPackage`: размер и SHA-256). `POST /api/voice {id}` скачивает голос (и в первый раз программу озвучки) в фоне; у этого скачивания своё состояние `vdl` (`tts.download` в `/api/state`), оно не переключает окно на экран скачивания и не мешает переводу; пока оно идёт, программа не выходит. Архивы `.tar.bz2` распаковываются (`untar`, без путей за пределы папки) и удаляются; путь к программе — в `engine/<os>-<arch>/tts.json`. Скачанный голос выбирается для своего языка (`voices` в `config.json`); голос, который читает язык (`activeVoiceID`), — выбранный, а если его нет — первый скачанный этого языка в каталоге. `POST /api/tts {lang, text, speed}` запускает `sherpa-onnx-offline-tts` (по одной фразе за раз, `ttsMu`; до 60 с) и возвращает WAV; рабочая папка — `models/voices`, пути к голосу — относительные и только латиницей, перед текстом — `--` (текст, начинающийся с `--`, остаётся текстом). Windows: программа читает командную строку в кодировке системы, поэтому рядом создаётся её копия `…-utf8.exe`, где встроенный манифест заменён (той же длины) манифестом с `activeCodePage UTF-8` (Windows 10 1903+); если копия не запускается, берётся сама программа (`ttsNoUTF8`). Оставшиеся от прошлого запуска `tts-*.wav` удаляются при старте.

**Каталог моделей** (`modelSpecs` в `main.go`): `ID, Name, Group, Family, Note, File, URL, Page, Size, SHA256`. С 0.7 — четыре модели Gemma 4: `g4-e2b` (E2B · Q4_0, по умолчанию — `defaultModelID`), `g4-e2b-q8`, `g4-e4b`, `g4-e4b-q8`; Q4_0 — из репозиториев google (QAT), Q8_0 — из ggml-org. Семейства: `chat` (Gemma 4 и свои файлы) и `hymt` (свои файлы Hy-MT2). Свои файлы `.gguf` из `models/` попадают в список сами (`file:<имя>`; «Hy-MT» в имени → семейство hymt) — так в списке остаются и Hy-MT2, скачанные до 0.7. Если выбранной модели больше нет в каталоге, выбирается `g4-e2b` (`ensureActiveValid`).

**Язык интерфейса и настройки.** Язык (`ui_language`: ru, en, de), тема (`theme`: light, dark), размер шрифта (`font_scale`: 90, 100, 115, 130) и настройки запуска (`show_welcome`, `launch_mode`: window, tab, `start_maximized`, `load_model_at_start`) хранятся в `config.json`, а не в браузере: окно-приложение и обычная вкладка браузера имеют разные хранилища. Меняются запросом `POST /api/settings`. Отдавая `index.html`, программа запуска заменяет тег `<html …>` на `<html lang="…" data-theme="…" data-font="…">` — окно сразу открывается на нужном языке, в нужной теме и размере. Сообщения программы запуска (ошибки, скачивание, заметки и группы каталога моделей) проходят через `tr()` (`i18n.go`): ключ — русский текст, переводы — `msgEN`, `msgDE`; язык меняется сразу после `POST /api/settings`. Сообщения до чтения `config.json` (ошибки запуска) — по-русски.

**Безопасность.** Принимаются только запросы к 127.0.0.1/localhost; запросы с изменением данных — только со своей страницы (заголовок Origin). Движку передаётся случайный ключ API, интерфейс его не знает. Имена файлов словарей проверяются (никаких путей и зарезервированных имён Windows).

### HTTP API программы запуска

| Путь | Метод | Назначение |
|---|---|---|
| `/api/ping` | GET | признак программы и версия |
| `/api/state` | GET | состояние: phase (setup, downloading, starting, ready, unloaded, error), `no_model_at_start`, `start_done`, модели (с `url`, `file`), движок (с `url`, `dir`), папка моделей, скачивание, настройки, сведения о компьютере; `tts` — программа озвучки (`engine`: есть ли, откуда, куда), голоса (`voices`: скачан, выбран, лицензия, `parts` — откуда и какие файлы), папка голосов, скачивание голоса (`download`); `window` — окно приложения: `available` (есть ли программа окна), `error` (почему не открылось), `pages` (страниц в нём) |
| `/api/events?page=…[&ttw=1]` | GET | поток событий окна (номер окна — `page`; `ttw=1` — страница в своём окне); пока он открыт, программа работает |
| `/api/closing?page=…` | POST | окно закрывается или перезагружается (sendBeacon); ответ 204 |
| `/api/setup`, `/api/cancel` | POST | скачать недостающее / отменить скачивание |
| `/api/restart` | POST | перезапустить движок |
| `/api/unload`, `/api/load` | POST | выгрузить модель из памяти (`{"at_start": true}` — из окна приветствия при запуске) / загрузить снова |
| `/api/start-done` | POST | окно приветствия закрыто: его выбор о модели больше не применяется в этом запуске |
| `/api/model` | POST `{id}` | выбрать модель (скачать при необходимости и загрузить) |
| `/api/model/{id}` | DELETE | удалить файл неактивной модели |
| `/api/saved-files` | GET / POST `{name, copy_from}` | список файлов сохранённых в `data/saved` (в пустой папке при первом запросе создаётся «Сохранённые.tsv» — имя на языке интерфейса) / новый файл или копия (имя занято — 409) |

### config.json

`active_model`, `ui_port` (8765), `ctx_size` (4096; это и память чата), `threads` (0 — авто), `engine_path` (свой llama-server), `extra_engine_args`, `open_window`, `ui_language` (ru), `theme` (light), `font_scale` (100), `show_welcome` (true), `launch_mode` (window — окно приложения; tab — вкладка браузера; прежнее app читается как window), `start_maximized` (true), `load_model_at_start` (true), `voices` (голос каждого языка: `{"ru": "ru-ruslan"}`; пока голосов нет — поля нет). В `config.json` прежних версий новых полей нет — берутся значения по умолчанию.

## Интерфейс (`ui/index.html`)

В `<head>` — маленький скрипт: при запуске без программы запуска он ставит тему, размер шрифта и язык из памяти браузера (`tdoc.settings`) до первой отрисовки. Тёмная тема — `:root[data-theme="dark"]` (от настройки системы не зависит); размеры шрифтов — в `rem` от `html { font-size: 14px }`, ступени `data-font` 90/115/130 меняют эту основу.

Разделы скрипта по порядку:

0. **Язык интерфейса** — `UI_LANG` (из `<html lang>`), `LOCALE` (числа и даты), `t(текст, {подстановки})`: ключ — русский текст из кода, перевод — в `I18N`; нет перевода — остаётся русский.
1. **Настройки** — всё, что разумно менять без программирования: `LANGS` (языки, названия для модели, формы для вопросов), `STYLES`, `MAX_CHARS` (1000), `FAMILIES` (шаблоны запросов и параметры генерации для `hymt` и `chat`, включая шаблон терминов словаря), `EDIT` (правка на том же языке), `ASK` (чат: инструкция модели, параметры, длина ответа), `ASK_ABOUT` (вопросы кнопки «?»), `RANDOM` (кнопка «Случайно»: виды и темы для запроса, параметры, число повторных попыток), `NEED_MODEL_MSG` («Please load a model.»), `LESSON` (кнопка «Учебный пример»: виды примеров `kinds` — что написать, середина и последняя строка, уровни `levels`, темы — общие и для каждого языка, с названиями на трёх языках, запрос `prompt`, проверка перед показом `selfCheck` и `checkPrompt`, параметры `sampling` 0,2, `checkSampling` 0 — для проверки и «Уточнить», `chatSampling` — для упражнения, `minSimilar`), `LESSON_ASK` (вопросы «Учебного примера» в «Спросить модель»: упражнение и «Уточнить», на трёх языках), `STYLE_EXAMPLE` и `CTX_EXAMPLE` (примеры в пустых полях «Свой» стиль и «Контекст»), `SPEAK` (чтение вслух: длина куска, скорость речи), `GLOSS_*` (первый словарь: имя, языки `GLOSS_STARTER_LANGS`, термины с примечаниями), `START_TARGET` (язык справа в новом окне), `MATH` (защита формул LaTeX: включена ли, число повторов, пояснение для модели), `MATH_TESTS` (фразы с формулами для «Теста»), `TEST_STYLES` (стили «Теста»: нейтральный и разговорный). Там же — **«О программе» и «Справка»**: `CONTACT_EMAIL`, `SPONSOR_URL` (пока пусто — строка о поддержке без ссылки), `ABOUT`, `WHATS_NEW` («Что нового» в окне приветствия), `HELP` — тексты на трёх языках.
2. **Помощники и обработка текста** — очистка вставленного текста (PDF; формулы на время чистки заменяются метками из «личных» символов Юникода и не меняются), определение языка (`detectLang`: алфавит; для латиницы — частые слова и буквы; формулы не учитываются), очистка ответа модели, пословное сравнение (подсветка правок), chrF.
2а. **Формулы LaTeX** — `findMath` (где формулы: `$$…$$` и `$…$` по правилам pandoc, плюс «перед открывающим `$` нет цифры»; `\$` — знак доллара; `$` внутри `{…}` не закрывает строчную формулу; строчная формула не переходит через пустую строку), `maskMath` (формулы → метки `{F1}`…, одинаковые — одной меткой; если в тексте уже есть что-то вроде `{F1}`, текст идёт как есть), `unmaskMath` (метки → формулы, с допусками: Ф/Φ, регистр, пробелы, `\{…\}`, полноширинные скобки, лишние `$` и `` ` `` вокруг; метки несуществующих формул убираются; список потерянных формул), `stripMath` (текст без формул — для «Авто», подсказки о языке и словаря).
3. **Запросы к модели** — `buildPrompt` (перевод: термины словаря + шаблон семейства; правка: `EDIT`; текст с метками формул и пояснение `MATH.note` перед запросом — кроме перевода моделью Hy-MT2 (только её шаблоны) и «Замечаний» (видят формулы как есть)), `askVariant` (через него идут все варианты, «Другой вариант», обратный перевод и тест: метки в ответе → формулы; если метки не хватает — повтор с `MATH.remind` и другим seed, до `MATH.retries` раз, берётся лучший ответ; возвращает текст, `lost` и число запросов), `chat` / `chatOnce` (потоковый запрос, разбор ошибок, в том числе переполнения контекста).
4. **Языки и режим** — направление перевода, «Авто», правка при совпадении языков, подсказки; `swapLangs` — кнопка ↔ (язык текста и язык результата меняются местами, «Авто» заменяется определённым языком). Языки нового окна (`startLangs`): слева — язык интерфейса, справа — первый подходящий из `START_TARGET`; новое ли окно — по признаку `tdoc.window` в `sessionStorage` (при перезагрузке и смене языка интерфейса в «Настройках» он остаётся; при смене языка в окне приветствия и на экране первого запуска — сбрасывается, и языки ставятся заново). `langMismatch` / `#langHint` — подсказка, если слева выбран язык, а текст явно на другом (разные алфавиты — сразу; языки с латиницей — от 4 слов и 25 букв).
5. **Стили и карточки вариантов** — по очереди нейтральный и выбранные стили; одинаковые результаты объединяются; у карточки: копировать, сохранить, обратный перевод / правки, «?», другой вариант. Под карточками — **«Свой вариант»** (`#ownCard`, `OWN`): `resetOwn` при новом переводе (тот же текст, контекст и языки — поле остаётся), `ownFromVariant` («Взять вариант» — всплывающее меню готовых вариантов без «Замечаний»), `ownSave` (закладка: сохранить со стилем «Свой вариант»; после правки — удалить прежнюю запись и записать новую; без правки — убрать).
5а. **Случайно** — `randomText`: запрос к модели «одна пословица/поговорка/устойчивое выражение на языке текста на случайную тему», очистка ответа (`cleanRandom`), отсечение повторов, подтверждение второго нажатия, если в поле уже есть текст.
5б. **Учебный пример** — `lessonText`: запрос `LESSON.prompt` (вид `lessonKind()` — не из двух последних; уровень `lessonLevel()`; тема `lessonTopicFor(язык)` — выбранная в окошке, своя или случайная, не из последних четырёх) на языке текста, как у «Случайно»; очистка ответа (`cleanLesson`: без разметки Markdown и лишних пустых строк, длиннее `LESSON.maxChars` — ошибка), отсечение повторов, подтверждение второго нажатия. Затем, если включено (`lessonSelfCheckOn`, `tdoc.lessonSelfCheck`), — проверка перед показом: `LESSON.checkPrompt` с температурой 0, ответ разбирает `lessonCheckResult` («OK» — пример верен; иначе исправленный пример, взятый после строки вида «Исправленный пример:», если он похож на исходный — `wordOverlap` ≥ `minSimilar` — и на том же языке — `detectLang`; иначе остаётся исходный). После вставки под полем — «Пример придуман моделью — возможны неточности и ошибки» (в подсказке — что показала проверка) и кнопка «Уточнить» (`showLessonNote`, `setNote(…, true)` — на своей строке; исчезает при правке текста). Две кнопки не ждут подтверждения одновременно. Стрелка `#lessonMore` — окошко `openLessonMenu` (на `openPop`): уровень (`.seg`), тема (`#lessonTopicSel`, «Своя тема…» — поле `#lessonOwnTopic`), галочка «Проверять пример перед показом» (`#lessonSelfCheck`), действия «Пример в поле текста», «Упражнение в «Спросить модель»» (`lessonExercise`) и, если пример в поле, «Уточнить пример в поле» (`lessonCheck`). Выбор — в памяти браузера (`tdoc.lessonLevel`, `tdoc.lessonTopic`, `tdoc.lessonOwnTopic`, `tdoc.lessonSelfCheck`). Упражнение и проверка — обычные вопросы в «Спросить модель» (`askAboutSend(вопрос, {sampling})`, `LESSON_ASK`): их видно в переписке, а ответы пользователя модель проверяет, потому что видит всю переписку.
5в. **Чтение вслух** — `speakToggle(кнопка, что подсвечивать, текст, язык)`: кнопки `button.speak` (`#srcSpeak`, `data-act="speak"` у карточки, `#ownSpeak`, у ответа в чате); `speechChunks(текст, язык)` (без формул и разметки, куски по предложениям до `SPEAK.maxChunk`; китайский — до `SPEAK.maxChunkZh`, предложения кончаются на 。！？； и без пробела, длинное делится по «，» и «、», куски склеиваются без пробела), `playChunk` (запрос `/api/tts`, `Audio`, следующий кусок запрашивается заранее), пауза и продолжение, `stopSpeech` (кнопка ■ `speakStopButton` рядом с 🔊, другая кнопка, Esc, новый перевод, исчезнувший текст; правка поля, которое читается, — `stopSpeechOnEdit`: ввод, а на паузе и фокус). Пока звучит: у кнопки класс `speaking` (зелёная, значок паузы), у текста — `speaking-host`; на паузе — у кнопки `paused` (зелёная рамка), подсветки текста нет. `voiceFor(язык)` — выбранный скачанный голос; без него у кнопки класс `no-voice` (бледная). Голоса в меню моделей — `renderVoiceMenu` (скачать с вопросом `showVoiceConfirm`: у голоса из частей — все адреса и «Файлы:»; выбрать, отменить, удалить); `renderTTSState` после каждого опроса — кнопки, строка `#ttsInfo` внизу окна, сообщение об окончании скачивания (опрос во время скачивания — раз в 0,7 с). Без программы запуска у `body` класс `no-tts` и кнопок нет.
6. **Сохранённые** — файлы в `data/saved` (выбранный — `tdoc.savedFile`); выбор файла и меню «⋯» (новый, копия, импорт, экспорт в .tsv и .txt, папка), поиск (все слова, ё = е, подсветка), «В поле» (текст и языки записи — в поле; другой текст в поле заменяется после второго нажатия). Закладка помнит, в какой файл сохранила (`c.savedFile`), и снимается из него. Импорт (`parseSavedImport`): таблица программы по названиям столбцов, текстовый экспорт программы (`parseSavedText`), простая таблица «текст — перевод» (языки — из заголовка или по тексту), список строк; повторы пропускаются. Файл, изменённый снаружи, перечитывается при возврате фокуса в окно.
7. **«Спросить модель»** — переписка целиком отправляется модели при каждом вопросе (сама модель ничего не помнит); старые пары реплик отбрасываются, когда не помещаются в контекст (оценка по длине + ответ движка о переполнении). «Обновить» стирает переписку. `askSend({sampling})` — свои параметры генерации для одного вопроса (упражнение и проверка «Учебного примера»).
8. **«?» у варианта** — всплывающее меню, вопросы из `ASK_ABOUT` с исходным текстом, вариантом, стилем и терминами.
9. **Словарь терминов** — таблица «столбец на язык + Примечание»; разбор TSV/CSV (кавычки Excel), автоопределение языков столбцов по заголовку или содержимому, перекодировка; поиск терминов в тексте по основе слова; автосохранение через 0,6 с; перечитывание файла, изменённого снаружи; импорт с объединением, экспорт (системный диалог сохранения или скачивание). Найденные термины уходят в запрос: для Hy-MT2 — шаблон «Reference the following translations» из README модели, для остальных — блок «Glossary: …» перед инструкцией.
10. **Тест** — пары EN/RU из `ui/tests.txt`, перевод в обе стороны в стилях `TEST_STYLES` (нейтральный и разговорный) + исправление; фразы `MATH_TESTS` в обе стороны (задания `kind: 'math'`); отчёт Markdown + JSON (у заданий с формулами — `formulas`, `lost`, `tries`; раздел «Формулы LaTeX»).
11. **Состояние программы и меню моделей** — опрос `/api/state` и `setModelState`. Экраны: рабочее окно `mainView` (показывается всегда, кроме первого запуска), `setupView` (нужно скачать файлы), `byeView` («Программа закрыта»). Над рабочим окном — плашка `#modelBanner`: загрузка модели (синяя), модель выгружена (жёлтая), ошибка движка или «программа не отвечает» (красная). Состояние модели — атрибут `body[data-model]`: `ready`, `starting`, `unloaded`, `error`, `setup`, `bye`; по нему кнопки с классом `needs-model` становятся бледными (но нажимаются: `needModel()` показывает подсказку). `quitApp` — «Выход» с подтверждением вторым нажатием. `PAGE_ID` — номер окна для `/api/events` и `/api/closing`. Нескачанная модель в меню — `showDlConfirm`: вопрос, откуда (`url`), куда (`models_dir`), файл; «Скачать» / «Отмена». Экран первого запуска показывает то же для движка и модели (`kvList`). Шапка справа: ⚙, модель и ⏏, «Сохранённые», «Тест», «?», T («О программе»), «Выход»; вне рабочего окна ⚙, «Сохранённые», «Тест», «?» и T скрыты.
12. **Настройки, справка, «О программе»** — панели `settingsView`, `helpView`, `aboutView`; `saveSettings` (через `/api/settings` или в память браузера; `settingsSeq` — ответ `/api/state`, запрошенный до изменения, его не затирает), `setUiLanguage(lang, how)` (сохранить, запомнить текст, контекст и открытую панель в `sessionStorage` `tdoc.keep`, перезагрузить окно; `how` = `welcome` или `setup` — сбросить `tdoc.window`), `setTheme`, `setFontScale`, `setStartOption` (вид окна и «При запуске» — `#startRows`, только с программой запуска); `translateStatic` — тексты и подсказки разметки HTML на язык интерфейса, один раз при запуске.
12а. **Окно приветствия** — `#welcomeView` поверх всего (ниже всплывающих сообщений). `maybeWelcome` после первого ответа `/api/state`: только с программой запуска, пока запуск не закончен (`start_done`), если в этом окне его ещё не было (`sessionStorage` `tdoc.welcome`) и включено `show_welcome`, или после смены языка в нём самом. `renderWelcome` (версия, `WHATS_NEW`, язык, вид окна, галочки — каждая сохраняется сразу), `closeWelcome` (если открыто при запуске и `start_done` ещё нет — загрузить или выгрузить модель по галочке; затем `/api/start-done`). Кнопка «Окно приветствия» в «Настройках» открывает его без действий с моделью. Кнопки: «Начать работу», «Выйти» (`#welcomeQuit` — тот же `quitApp` с общим подтверждением; окно приветствия при выходе просто скрывается, модель не трогается), «О программе». Окно двигается мышью (`initWelcomeDrag`: pointer events на `.panel.welcome`, кроме кнопок, полей, списков и подписей галочек; сдвиг — `transform`, `setWelcomeShift`; не дальше края окна — виден заголовок и полоса `WELCOME_DRAG_KEEP` точек; при открытии и если после изменения размера окна оно оказалось за краем — снова на месте).
13. **Переводы интерфейса** — `I18N`: `'русский текст': ['English', 'Deutsch']`; формы числа — `'форма для 1': [['one', 'many'], ['ein', 'viele']]` (для `plural()`). Полноту проверяет `source/tests/i18n_check.py`.
14. **Привязка событий** (`init`). Словарь и файл сохранённых открываются, когда впервые показано рабочее окно (`showMain`), — после экрана первого запуска, где можно выбрать язык: первые файлы получают имена на этом языке.

**Окно приложения.** `OWN_WINDOW` — страница открыта в окне приложения (есть функции окна `ttwSaveFile`, `ttwOpenExternal`, `ttwClose`). Тогда: ссылки на другие сайты и `mailto:` перехватываются и открываются снаружи (`ttwOpenExternal`); экспорт словаря и «Сохранённых» — через `ownSaveFile` (окно «Сохранить как» системы); «Выход» закрывает окно (`ttwClose`); поток событий — с `ttw=1`. Вид окна в «Настройках» и окне приветствия — `renderModeSeg`: «Окно приложения» (`window`) и «Вкладка браузера» (`tab`); в «Настройках» — галочка `#setMax` (`start_maximized`, недоступна для вкладки) и причина неудачи `#modeErr` (`window.error`).

**Два режима.** С программой запуска (`MODE = 'launcher'`) — всё доступно. Запасной запуск (`start.bat` / `start.sh`, `MODE = 'basic'`): llama-server сам отдаёт `ui/`, нет меню моделей, выгрузки, окна приветствия и кнопки «Выход», сохранённые и словарь хранятся в браузере (localStorage), семейство модели определяется по имени файла из `/props`.

**Хранение в браузере** (ключи `tdoc.*`): выбранные стили и языки, свой стиль, открытый словарь и переключатель словаря, выбранный файл сохранённых, вкладка нижней панели; в запасном режиме — сохранённые, словарь и настройки интерфейса (`tdoc.settings`). В `sessionStorage` (живёт, пока открыто окно): `tdoc.window` — окно уже открывалось (языки не сбрасываются), `tdoc.welcome` — окно приветствия в этом окне уже закрыто, `tdoc.keep` — текст, контекст и панель на время перезагрузки при смене языка.

## Форматы файлов

- **Сохранённые** (`data/saved/*.tsv`) — UTF-8 с BOM, CRLF, табуляции: `id, время, с, на, стиль, исходный текст, перевод, контекст`. Ячейка с кавычкой — в кавычках, как в Excel; переводы строк внутри текста заменяются пробелами. При чтении: UTF-16 и кодировки Windows перекодируются; строке без id даётся id из хеша её текста (`r…`), повторный id получает суффикс `-2`; столбцы правее восьмого и заголовок сохраняются при перезаписи. Заголовок столбцов — по-русски при любом языке интерфейса (это формат файла). Запись — во временный файл и переименование. При запуске `data/saved.tsv` (версии до 0.5.1) переносится в `data/saved/Сохранённые.tsv` (имя занято — «(2)»), только в работающей копии программы.
- **Текстовый экспорт сохранённых** (.txt) — на языке интерфейса: первая строка «Ttranslator · сохранённые переводы · «файл» · дата · N записей», затем блоки: «№ N · направление · стиль · время», текст, «→ перевод», при наличии «Контекст: …»; пустая строка между блоками. Импорт узнаёт такой файл на любом из трёх языков.
- **Словарь** (`data/glossary/*.tsv`) — UTF-8 с BOM, CRLF, табуляции (или «;»/«,» для .csv); первая строка — языки (`Английский`, `Русский`… или `en`, `ru`…) и `Примечание`; дальше по термину в строке. Поля с кавычками или разделителем — в кавычках, как в Excel.
- **Отчёт теста** — `test-ГГГГ-ММ-ДД_чч-мм-сс.md` (для чтения) и `.json` (данные: компьютер, движок, модель, параметры, словарь, результаты).

## Как обновить движок или добавить модель

- **Движок:** `engineVersion` в `main.go` и в `currentEnginePackage()` — имя архива, размер и SHA-256 для Windows и Linux (берутся со страницы выпуска на GitHub); проверить запуск обеих сборок; обновить ссылку в README.
- **Значок:** контур `LOGO` в `index.html`; после его изменения — `cd source/launcher && go run make_icon.go` (пишет `rsrc_windows_amd64.syso` и `Ttranslator.ico`; `icon_check.py` проверяет, что они соответствуют контуру и попали в Ttranslator.exe).
- **Модель в каталог:** закрепить ссылку на коммит (`.../resolve/<коммит>/<файл>`), взять размер и SHA-256 из LFS-указателя (`.../raw/<коммит>/<файл>`), выбрать семейство (`chat` или `hymt`) и написать заметку о скорости относительно Gemma 4 E2B.
- **Голос в каталог:** `piperVoice(...)` в `voiceSpecs` (`tts.go`): архив `vits-piper-<голос>.tar.bz2` из выпуска `tts-models` sherpa-onnx — его размер и SHA-256 (скачать и посчитать), лицензия из `MODEL_CARD` (у набора данных; некоммерческая — `nc: true`), пол, ссылка на образцы; у модели с несколькими дикторами — `speaker(..., sid)` (номер — из `speaker_id_map` в `.onnx.json`). **Перед этим — `python3 source/tests/voice_check.py`** (с `--voices=файл.json` — кандидат, которого ещё нет в `tts.go`): голос читает фразы своего языка, Whisper их распознаёт; голос с вердиктом не «ok» (речь заметно длиннее текста или больше 60 % слов не те) — не брать. Образец на сайте Piper — одно длинное предложение, по нему такой изъян не слышен (так было с MLS 9972). Лицензии видны в меню моделей, `README.txt` и «О программе». Голос с `lexicon.txt` вместо `espeak-ng-data` (китайские) — `lexiconVoice(piperVoice(...), "lexicon.txt", правила .fst…)`. Голоса нет в архивах выпуска (чаще всего не случайно — проверить `voice_check.py`) — `partsVoice(...)`: модель и `tokens.txt` со страницы `huggingface.co/csukuangfj/vits-piper-<голос>` (тот же конвертер sherpa-onnx; адрес — `resolve/<коммит>/`), `espeakPart`; SHA-256 модели — из указателя Git LFS (его хэш Git совпадает с `oid` в списке файлов), у мелких файлов — посчитать по содержимому и сверить хэш Git с `oid`. Пол голоса, если не указан, — по высоте голоса в образце (сравнить с голосами известного пола).
- **Программа озвучки:** `ttsVersion` и `currentTTSPackage()` в `tts.go` — имена общих (shared) архивов выпуска sherpa-onnx, их размеры и SHA-256; в Windows проверить, что `sherpa-onnx-offline-tts.exe` по-прежнему со встроенным манифестом MSVC (иначе копия с UTF-8 не создаётся, и русский текст на немецкой Windows не прочитается); в `run_all.sh` — `TTS`, `TTS_SHA`.
