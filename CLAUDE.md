# CLAUDE.md — для любой сессии Claude в этом репозитории

Ttranslator — локальный офлайн-переводчик: программа запуска на Go, интерфейс — один файл `ui/index.html`, движок llama.cpp. Автор идеи и всех решений о поведении программы — владелец репозитория (Allasoneteam); он учёный, не программист. Общение с ним — по-русски, просто и по делу.

Сначала прочитай `source/CLAUDE.md` (правила работы над кодом) и `source/docs/DEVELOPMENT.md` (сборка, тесты, облачная среда); по мере надобности — `source/docs/ARCHITECTURE.md` (устройство) и `source/docs/ROADMAP.md` (планы и решения автора). Если тебе дали задание из `.claude/tasks/`, прочитай его целиком и держись его; после сжатия контекста перечитай.

## Жёсткие правила (репозиторий открыт: всё отправленное видят все)
- Ветки: работай только в своей ветке (у облачной сессии — та, что создана для неё, обычно `claude/…`), основа — `origin/dev`. Не отправляй в `main` и `dev`, не удаляй ветки, не создавай метки и выпуски, не меняй настройки репозитория. В `dev` работу сливает координатор (чат проекта автора) после проверки; в `main` и выпуски — только после «да» автора.
- Запрос на слияние (PR), если создаёшь: в `dev`, черновиком (draft); никогда — в `main`.
- Коммиты: автор и коммиттер — `Ttranslator authors <Ttranslator@proton.me>`; до первого коммита: `git config user.name "Ttranslator authors"` и `git config user.email "Ttranslator@proton.me"`. Сообщения коммитов — по-английски.
- Никаких личных данных в репозитории: имён, адресов почты, путей на компьютере автора, содержимого `config.json`, `data/`, `models/`, `engine/`.
- Новые сторонние компоненты (библиотеки, программы, сервисы) — только с согласия автора: опиши варианты и спроси; не добавляй сам (исключения названы в задании).
- Программа скачивает только с официальных источников, с закреплённой версией, размером и SHA-256.
- Перед каждой отправкой: `bash source/tests/run_all.sh <рабочая-папка>` — `ALL SUITES PASSED`; новый текст интерфейса — сразу на пяти языках.

## Облачная сессия
- В начале один раз: `bash .claude/cloud_setup.sh` (системные пакеты и модули Python для тестов, несколько минут).
- Отправляй работу в свою ветку по ходу — после каждого законченного шага: сессию может прервать лимит, контейнер — сброс.
- GitHub Actions (`.github/workflows/ci.yml`) запускается при каждой отправке в любую ветку: тесты, сборки Windows и Linux, а также шаги `macos` (запускает `source/ci/macos.sh`) и `android` (запускает `android/ci.sh`), если эти скрипты есть. Итоги — `gh run list --branch <ветка>`, `gh run view <id> --log-failed` или REST-запросы `gh api` (GraphQL может быть недоступен).
- Сам файл `.github/workflows/ci.yml` по возможности не меняй: всё нужное — в своих скриптах. Если без изменения не обойтись и отправку отклонят, опиши нужное изменение в отчёте — его внесёт координатор.

## Когда закончил (или застрял)
Отчёт автору по-русски, коротко: что сделано, что проверено (ссылки на запуски CI), что не получилось, что проверить ему руками. Тот же текст — в описании PR или в файле, который называет задание.
