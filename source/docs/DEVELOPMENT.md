# Разработка: сборка, тесты, выпуск версии

## Сборка

- Нужен Go 1.24 или новее, больше ничего: программа запуска использует только стандартную библиотеку.
- В папке программы: `sh source/build.sh` — собирает `Ttranslator.exe` и `ttranslator-linux` прямо в папку программы (и кладёт копию `ui/` внутрь исполняемого файла как запасную; временная папка `source/launcher/ui_fallback` создаётся сборкой и в папку пользователя не доставляется).
- `go vet ./...` и `GOOS=windows go vet ./...` в `source/launcher` — проверка обеих версий.
- Значок Ttranslator.exe — файл `source/launcher/rsrc_windows_amd64.syso`, `go build` для Windows вставляет его сам. После изменения рисунка (`LOGO` в `index.html`): `cd source/launcher && go run make_icon.go` (пишет и `Ttranslator.ico` — значок программы окна, и `Ttranslator.png` — значок окна в Linux).
- Окно приложения (`source/window`, C++): `sh source/window/build.sh` — `ttranslator-window.exe` (MinGW-w64, статически) и `ttranslator-window-linux` в папку программы; `source/build.sh` собирает их сам, если инструменты есть. Нужно (Ubuntu/Debian): `g++ pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev g++-mingw-w64-x86-64`. Подробно — `source/window/README.md`.
- Архивы выпуска: `sh source/release.sh [папка]` после сборки (по умолчанию — `dist/` в папке программы; `BIN_DIR` — где собранные программы, `ENGINE_CACHE` — где держать архивы движка): `Ttranslator-<версия>-windows-x64.zip`, `Ttranslator-<версия>-linux-x64.tar.gz` и `SHA256SUMS.txt`; в каждом — папка `Ttranslator/`, готовая к запуску, с движком внутри (устройство — `ARCHITECTURE.md`, «Папка программы»). Нужны `go`, `python3`, `curl`, `zip`, `unzip`, `tar`.
- GitHub: `.github/workflows/ci.yml` — при каждой отправке в любую ветку (`main`, `dev`, ветки облачных сессий `claude/…`; новая отправка в ту же ветку отменяет незаконченный запуск) все тесты (Ubuntu 24.04) и сборка всех программ (Ubuntu 22.04: программа окна для Linux тогда работает и на старых системах) с контрольными суммами, а из них — архивы выпуска; собранное и архивы (каждый архив — отдельным артефактом, без второй упаковки в zip) — в артефактах запуска, 14 дней. Шаги `macos` (машины GitHub `macos-15-intel` — x64 и `macos-15` — arm64) и `android` (Ubuntu 24.04) запускают `source/ci/macos.sh <arch> <out-dir>` и `android/ci.sh <out-dir>`, если они есть; всё из `<out-dir>` — артефакты запуска, а строка `MACZIP=<имя архива>` в `$GITHUB_ENV` выгружает архив для Mac отдельным артефактом. Выпусков CI не делает: публикация — только после «да» автора.

## Тесты

- Всё сразу: `bash source/tests/run_all.sh` (Linux, несколько минут) — см. `source/tests/README.md`.
- Настоящие модели в тестах не нужны (и в облачной среде Claude их не скачать: huggingface.co там недоступен). Качество перевода проверяется на компьютере пользователя кнопкой «Тест»; отчёты разных моделей лежат в `data/reports` и сравнимы между собой.
- Окно приложения проверяется по-настоящему под виртуальным экраном (`xvfb-run`): программа запуска с окном приложения (`e2e_window.py`; с оконным менеджером openbox — и то, что окно открылось на весь экран) и функции окна для страницы (`window_functions.py`, окно «Сохранить» подтверждается через `xdotool`); программа окна для Windows — только собирается (и проверяется, что ей нужны лишь системные DLL). Нужно: `xvfb xdotool imagemagick openbox x11-utils` и инструменты сборки окна; без них эти наборы пропускаются (без openbox — только проверки «на весь экран» и «впереди активного окна»; `xmessage` из `x11-utils` изображает окно папки). В контейнере без пространств имён пользователя WebKitGTK запускается с `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1` (только в тестах). Окно Windows (WebView2) проверяет пользователь; в облачной среде — запуск под Wine без WebView2: код 3 и запасной путь.
- Чтение вслух проверяется по-настоящему: `run_all.sh` один раз скачивает с github.com программу sherpa-onnx для Linux, четыре голоса Piper (английский, русский, китайский со словарём произношения и испанский Sharvard — диктор F модели с двумя дикторами) и `espeak-ng-data` (около 310 МБ, кэш в рабочей папке) и отдаёт их программе запуска через локальное зеркало (`TDOC_TTS_URL`, `TDOC_TEST_VOICES`). Голос «из частей» (так в 0.9.3 скачивался испанский MLS 9972; сейчас таких в каталоге нет) проверяется на частях английского голоса (`voices093.json`, `e2e_v093.py`). Windows-копию программы озвучки с UTF-8 проверяет только модульный тест (`TestPatchManifestUTF8`); как она работает на настоящей Windows, проверяет пользователь (русский текст на 🔊).
- Читает ли голос то, что ему дали: `python3 source/tests/voice_check.py [рабочая-папка]` (не входит в `run_all.sh`: в первый раз скачивает около 1 ГБ с github.com — sherpa-onnx, Whisper base и все голоса каталога; 3–4 минуты). Каждый голос читает восемь фраз своего языка, Whisper их распознаёт; итог по голосу — секунды речи на знак текста и доля неверных слов, `ok` или `SLOW`/`WORDS`. Голос другого языка (латынь — итальянский Paola, 1.0) читает фразы, переписанные так же, как в программе (`TestDumpRespell`; классическое произношение — `TDOC_RESPELL_KIND=classical` и копия модели с голосом espeak-ng «la», как `espeakModel`), Whisper слушает на языке голоса, а сравниваются буквы, не слова. Запускать перед тем, как голос попадёт в каталог (`--voices=файл.json` — кандидат, которого ещё нет в `tts.go`), и после смены версии sherpa-onnx. `--keep` оставляет WAV, чтобы послушать.
- Каждая новая функция получает свои проверки.
- Новый текст интерфейса — через `t('…')` с переводом в `I18N` (английский, немецкий, испанский, китайский), иначе не пройдёт `i18n_check.py`; новое сообщение программы запуска — через `tr("…")` с переводом в `msgEN`, `msgDE`, `msgES` и `msgZH` (`i18n.go`), иначе не пройдёт `TestTranslations`.

## Выпуск новой версии

1. Изменения в коде (`source/launcher`, `ui/index.html`, при необходимости `start.bat` / `start.sh`).
2. Номер версии: `appVersion` в `source/launcher/main.go`.
3. `README.txt`: раздел «Что нового», описание новых функций; `source/docs/CHANGELOG.md`; при изменении устройства — `ARCHITECTURE.md`; выполненное — убрать из `ROADMAP.md`. Новые файлы `.go` и тесты — в списки ниже и в `source/tests/README.md`.
4. `run_all.sh` — все наборы проверок проходят.
5. Сборка обеих версий.
6. Архивы: `sh source/release.sh` (проверяет `release_check.py` в `run_all.sh`; в GitHub Actions они собираются сами — для проверки на другом компьютере их можно скачать со страницы запуска).
7. Доставка в папку программы: только файлы программы — `Ttranslator.exe`, `ttranslator-linux`, `ttranslator-window.exe`, `ttranslator-window-linux`, `ui/index.html`, `README.txt`, `README.md`, `LICENSE.txt`, `start.bat`, `start.sh`, `.gitignore`, `.gitattributes`, `CLAUDE.md`, `source/...` (без `source/launcher/ui_fallback`). Папки `.github` (настройки GitHub Actions) и `.claude` (задания и инструменты облачных сессий) — только в репозитории: на компьютер пользователя инструменты Claude их не записывают. Не трогать `config.json`, `data/`, `models/`, `engine/`, `ui/tests.txt`.
8. Проверка: SHA-256 доставленных файлов совпадают с собранными. Исключение — картинки PNG (`source/launcher/Ttranslator.png`): при передаче на компьютер пользователя они перекодируются (картинка та же, байты другие), их сверять по пикселям.

## Облачные сессии Claude

- Обычная облачная сессия (claude.ai/code) видит только репозиторий: правила — `CLAUDE.md` в корне, задания — `.claude/tasks/`. Знания проекта и компьютер автора ей недоступны: запись в папку программы автора — только из чата проекта (координатора).
- Среда: `bash .claude/cloud_setup.sh`, затем `bash source/tests/run_all.sh <рабочая-папка>` (10–20 минут; один раз качает около 310 МБ с github.com, кэш — в рабочей папке).
- Ветки: сессия работает в своей ветке (обычно `claude/…`) от `dev`; запрос на слияние — черновиком в `dev`; сливает координатор, в `main` — только после «да» автора.
- Прокси облака: отправка веток и `--force` — можно; метки, удаление веток, выпуски, настройки репозитория и GraphQL (`gh pr list`, `gh issue list`) — нельзя: это делает автор в браузере, а вместо GraphQL — REST (`gh api 'repos/Allasoneteam/Ttranslator/pulls?state=all'`). Отправку с изменением `.github/workflows` из облачной сессии могут отклонить — поэтому шаги macOS и Android запускают скрипты репозитория.
- Из облака недоступны huggingface.co (curl) и rhasspy.github.io; файлы выпусков GitHub и raw.githubusercontent.com — доступны.
- `pkill -f слово` убивает и свою оболочку, если слово есть в её команде: писать `pkill -f "[m]irror_server[.]py"`.
- `ffmpeg` в цикле `while read` съедает stdin — `ffmpeg -nostdin`.
- `run_all.sh` показывает только последние 60 строк набора: при «FAILS: N» без строк FAIL — перезапустить набор отдельно (как `start_launcher`: своя папка, `config.json` с ru или без него, порт; зеркало `mirror_server.py` на 18080).
- В выводе тестов не писать «файл.go: текст»: `actions/setup-go` принимает это за ошибку Go.
- Правка документов скриптом Python: `"models\voices"` в обычной строке превращается в `\v` — писать `r"..."`; `README.txt` читать с `newline=''`, иначе CRLF не видно.
- Минимальная версия macOS у файлов других проектов (движок, sherpa-onnx) — `python3 -I .claude/tools/macho_minos.py <папка>`.

## Мелочи, о которые легко споткнуться

- `README.txt` — UTF-8 с BOM и переводами строк CRLF (Блокнот в Windows); `start.bat` — только ASCII и CRLF.
- В Windows исполняемый файл нельзя заменить, пока программа запущена: перед обновлением её нужно закрыть. При переходе с 0.4 на 0.5 имя файла другое: старые `Translator.exe` и `translator-linux` остаются в папке, их нужно закрыть и удалить.
- Рабочее окно показывается и без модели, поэтому тесты ждут не `#mainView`, а `body[data-model="ready"]`.
- Интерфейс открывается с http://127.0.0.1 — это «безопасный контекст», поэтому в Edge/Chrome доступны буфер обмена и системный диалог сохранения файла.
- llama-server закрывает соединение после потокового ответа: программа запуска открывает новое соединение на каждый запрос (`DisableKeepAlives`) и сначала читает тело запроса целиком.
- Определение языка «Авто» срабатывает с задержкой 250 мс после ввода — в тестах ждать её.
- Новое окно получает языки «язык интерфейса → английский» и окно приветствия. Тесты, написанные для прежнего «Авто → Авто» и без окна приветствия, открывают окно как «не новое»: `ctx.add_init_script("sessionStorage.setItem('tdoc.window', '1'); sessionStorage.setItem('tdoc.welcome', 'done')")`; тест, которому нужно новое окно без приветствия, выключает его: `POST /api/settings {"show_welcome": false}` (`e2e_v061.py`).
- Нескачанная модель в меню скачивается только после «Скачать» в появившемся вопросе (`#modelMenu .dl-confirm button.primary`).
- Всё, что отправляет модели текст на перевод или правку, — через `askVariant` (формулы → метки, проверка ответа, повтор); прямой вызов `chat(buildPrompt(…))` для вариантов обошёл бы защиту формул.
- «Тест»: по 6 заданий на пару из `tests.txt` (4 перевода в стилях `TEST_STYLES` и 2 правки) и по 2 на фразу `MATH_TESTS`; с фразами 0.9 — 14 заданий. `e2e_v02.py` считает их сам по `tests.txt` и `MATH_TESTS`; `prompts_v08.py` подставляет свои три фразы с формулами.
- `e2e_v07.py` сам перезапускает программу запуска (через `/api/quit` и новый процесс с теми же `TDOC_ENGINE_URL` и `TDOC_TEST_MODELS`) — поэтому `run_all.sh` передаёт ему адрес движка и файл тестовых моделей.
- Программа выходит через 5 секунд после закрытия последнего окна. Поэтому `run_all.sh` держит у программ запуска фоновый поток событий (`curl … /api/events`), а тест закрытия окна (`e2e_v061.py`) запускается без него (`start_launcher … nokeep`).
- Смена языка интерфейса перезагружает страницу: в тестах — `with page.expect_navigation(): page.select_option('#uiLangSel', 'en')`, затем ждать `body[data-model="ready"]`.
- `start_launcher` в `run_all.sh` передаёт программе запуска переменные из `XENV` (так `e2e_v09.py` и `e2e_v093.py` получают зеркало программы озвучки и голосов). Зеркало (`mirror_server.py`) отдаёт файлы по имени без папок — поэтому у частей тестового голоса свои имена (`es-test-model.onnx`, `es-test-tokens.txt`), а имя файла в папке голоса — в `file`.
- `e2e_v093.py` заканчивается кнопкой «Выйти» в окне приветствия — программа запуска на порту 18785 завершается.
- С 1.0 новая установка открывается на английском, а наборы до 1.0 написаны для русского интерфейса: `start_launcher` кладёт в папку `config.json` с `"ui_language": "ru"`; `FRESH=1 start_launcher …` — без него (настоящая новая установка: так запускается `e2e_v10.py`). `basic_mode.py` (запуск без программы запуска) сначала открывает страницу в браузере без настроек (английский), потом записывает в память браузера русский.
- `e2e_v10.py` (1.0): новая установка — английский, список языков интерфейса; испанский на экране первого запуска, первые файлы и словарь по-испански; «Авто» справа по языку интерфейса; справка (12 разделов, «Обновление и удаление»), «О программе» (ссылки, благодарность), настройки (температура, ответы, скорость чтения — в `config.json` и в запросе «Спросить модель»), панель теста; подробный тест с латинскими парами `tests.txt` (38 заданий, ответы — заготовки), сводка и отчёт по направлениям, подписи строк; быстрый тест (латынь ↔ испанский, 4 задания, отчёт `quick-test-…`); оба латинских голоса в меню и в `/api/state`; китайский интерфейс (шрифты, формы числа, справка, быстрый тест латынь ↔ китайский); сообщения программы запуска по-испански и по-китайски.
- `e2e_v095.py` начинает со свежей папки (без `make_ready`), сам перезапускает программу запуска (как `e2e_v07.py`, с адресами движка и программы озвучки и тестовыми каталогами моделей и голосов; поток событий для перезапущенной держит сам) и в конце закрывает её (`/api/quit`). «Голос с другого компьютера» он делает, распаковывая архив голоса из зеркала в `models/voices`.
- `TestShortcut` проверяет ярлык `desktop-file-validate`, если он есть (пакет `desktop-file-utils`); без него — только содержимое.
- Распаковка `.tar.bz2` стандартной библиотекой Go небыстрая (голос 65 МБ — около 10 секунд в облачной среде): тесты ждут окончания скачивания по `/api/state`, а не фиксированное время.
- Без ответа программы запуска на `/api/state` (запасной запуск) у `body` класс `no-tts`: кнопок 🔊 нет.
- Сборка llama.cpp из исходников с `-march=native` не переносится на другой процессор; тесты используют официальный архив выпуска (выбирает вариант под процессор сам).
- Тесты окна приложения ищут процессы программы окна по `/proc/*/exe`, а не `pgrep -f`: по командной строке находится и сама оболочка, запустившая тест.
- Программа окна для Linux — с общей библиотекой C++: статическая (`-static-libstdc++`) потянула бы символы glibc 2.36–2.38 и не запустилась бы на Ubuntu 22.04 и Debian 12; `sscanf` и подобные функции в программе окна не использовать (в glibc 2.38 они стали `__isoc23_*`).
- В Windows программу окна нельзя запускать с флагами скрытого окна (`setChildAttrs`): первое `ShowWindow` взяло бы `SW_HIDE` из параметров запуска.
