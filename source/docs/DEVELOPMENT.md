# Разработка: сборка, тесты, выпуск версии

## Сборка

- Нужен Go 1.24 или новее, больше ничего: программа запуска использует только стандартную библиотеку.
- В папке программы: `sh source/build.sh` — собирает `Ttranslator.exe` и `ttranslator-linux` прямо в папку программы (и кладёт копию `ui/` внутрь исполняемого файла как запасную; временная папка `source/launcher/ui_fallback` создаётся сборкой и в папку пользователя не доставляется).
- `go vet ./...` и `GOOS=windows go vet ./...` в `source/launcher` — проверка обеих версий.
- Значок Ttranslator.exe — файл `source/launcher/rsrc_windows_amd64.syso`, `go build` для Windows вставляет его сам. После изменения рисунка (`LOGO` в `index.html`): `cd source/launcher && go run make_icon.go` (пишет и `Ttranslator.ico` — значок программы окна, и `Ttranslator.png` — значок окна в Linux).
- Окно приложения (`source/window`, C++): `sh source/window/build.sh` — `ttranslator-window.exe` (MinGW-w64, статически) и `ttranslator-window-linux` в папку программы; `source/build.sh` собирает их сам, если инструменты есть. Нужно (Ubuntu/Debian): `g++ pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev g++-mingw-w64-x86-64`. Подробно — `source/window/README.md`.
- GitHub: `.github/workflows/ci.yml` — при каждом изменении все тесты (Ubuntu 24.04) и сборка всех программ (Ubuntu 22.04: программа окна для Linux тогда работает и на старых системах) с контрольными суммами; собранное — в артефактах запуска. Выпусков CI не делает: публикация — только после «да» автора.

## Тесты

- Всё сразу: `bash source/tests/run_all.sh` (Linux, несколько минут) — см. `source/tests/README.md`.
- Настоящие модели в тестах не нужны (и в облачной среде Claude их не скачать: huggingface.co там недоступен). Качество перевода проверяется на компьютере пользователя кнопкой «Тест»; отчёты разных моделей лежат в `data/reports` и сравнимы между собой.
- Окно приложения проверяется по-настоящему под виртуальным экраном (`xvfb-run`): программа запуска с окном приложения (`e2e_window.py`; с оконным менеджером openbox — и то, что окно открылось на весь экран) и функции окна для страницы (`window_functions.py`, окно «Сохранить» подтверждается через `xdotool`); программа окна для Windows — только собирается (и проверяется, что ей нужны лишь системные DLL). Нужно: `xvfb xdotool imagemagick openbox` и инструменты сборки окна; без них эти наборы пропускаются (без openbox — только проверка «на весь экран»). В контейнере без пространств имён пользователя WebKitGTK запускается с `WEBKIT_DISABLE_SANDBOX_THIS_IS_DANGEROUS=1` (только в тестах). Окно Windows (WebView2) проверяет пользователь; в облачной среде — запуск под Wine без WebView2: код 3 и запасной путь.
- Чтение вслух проверяется по-настоящему: `run_all.sh` один раз скачивает с github.com программу sherpa-onnx для Linux и два голоса Piper (около 160 МБ, кэш в рабочей папке) и отдаёт их программе запуска через локальное зеркало (`TDOC_TTS_URL`, `TDOC_TEST_VOICES`). Windows-копию программы озвучки с UTF-8 проверяет только модульный тест (`TestPatchManifestUTF8`); как она работает на настоящей Windows, проверяет пользователь (русский текст на 🔊).
- Каждая новая функция получает свои проверки.
- Новый текст интерфейса — через `t('…')` с переводом в `I18N` (английский и немецкий), иначе не пройдёт `i18n_check.py`; новое сообщение программы запуска — через `tr("…")` с переводом в `msgEN` и `msgDE` (`i18n.go`), иначе не пройдёт `TestTranslations`.

## Выпуск новой версии

1. Изменения в коде (`source/launcher`, `ui/index.html`, при необходимости `start.bat` / `start.sh`).
2. Номер версии: `appVersion` в `source/launcher/main.go`.
3. `README.txt`: раздел «Что нового», описание новых функций; `source/docs/CHANGELOG.md`; при изменении устройства — `ARCHITECTURE.md`; выполненное — убрать из `ROADMAP.md`. Новые файлы `.go` и тесты — в списки ниже и в `source/tests/README.md`.
4. `run_all.sh` — все наборы проверок проходят.
5. Сборка обеих версий.
6. Доставка в папку программы: только файлы программы — `Ttranslator.exe`, `ttranslator-linux`, `ttranslator-window.exe`, `ttranslator-window-linux`, `ui/index.html`, `README.txt`, `README.md`, `LICENSE.txt`, `start.bat`, `start.sh`, `.gitignore`, `.gitattributes`, `source/...` (без `source/launcher/ui_fallback`). Папка `.github` (настройки GitHub Actions) — только в репозитории: на компьютер пользователя инструменты Claude её не записывают. Не трогать `config.json`, `data/`, `models/`, `engine/`, `ui/tests.txt`.
7. Проверка: SHA-256 доставленных файлов совпадают с собранными. Исключение — картинки PNG (`source/launcher/Ttranslator.png`): при передаче на компьютер пользователя они перекодируются (картинка та же, байты другие), их сверять по пикселям.

## Мелочи, о которые легко споткнуться

- `README.txt` — UTF-8 с BOM и переводами строк CRLF (Блокнот в Windows); `start.bat` — только ASCII и CRLF.
- В Windows исполняемый файл нельзя заменить, пока программа запущена: перед обновлением её нужно закрыть. При переходе с 0.4 на 0.5 имя файла другое: старые `Translator.exe` и `translator-linux` остаются в папке, их нужно закрыть и удалить.
- Рабочее окно показывается и без модели, поэтому тесты ждут не `#mainView`, а `body[data-model="ready"]`.
- Интерфейс открывается с http://127.0.0.1 — это «безопасный контекст», поэтому в Edge/Chrome доступны буфер обмена и системный диалог сохранения файла.
- llama-server закрывает соединение после потокового ответа: программа запуска открывает новое соединение на каждый запрос (`DisableKeepAlives`) и сначала читает тело запроса целиком.
- Определение языка «Авто» срабатывает с задержкой 250 мс после ввода — в тестах ждать её.
- Новое окно получает языки «язык интерфейса → английский» и окно приветствия. Тесты, написанные для прежнего «Авто → Авто» и без окна приветствия, открывают окно как «не новое»: `ctx.add_init_script("sessionStorage.setItem('tdoc.window', '1'); sessionStorage.setItem('tdoc.welcome', 'done')")`; тест, которому нужно новое окно без приветствия, выключает его: `POST /api/settings {"show_welcome": false}` (`e2e_v061.py`).
- Нескачанная модель в меню скачивается только после «Скачать» в появившемся вопросе (`#modelMenu .dl-confirm button.primary`).
- Всё, что отправляет модели текст на перевод или правку, — через `askVariant` (формулы → метки, проверка ответа, повтор); прямой вызов `chat(buildPrompt(…))` для вариантов обошёл бы защиту формул.
- «Тест»: по 6 заданий на пару из `tests.txt` (4 перевода в стилях `TEST_STYLES` и 2 правки) и по 2 на фразу `MATH_TESTS`; с фразами 0.9 — 14 заданий. `e2e_v02.py` считает их сам по `tests.txt` и `MATH_TESTS`; `prompts_v08.py` подставляет свои три фразы с формулами.
- `e2e_v07.py` сам перезапускает программу запуска (через `/api/quit` и новый процесс с теми же `TDOC_ENGINE_URL` и `TDOC_TEST_MODELS`) — поэтому `run_all.sh` передаёт ему адрес движка и файл тестовых моделей.
- Программа выходит через 5 секунд после закрытия последнего окна. Поэтому `run_all.sh` держит у программ запуска фоновый поток событий (`curl … /api/events`), а тест закрытия окна (`e2e_v061.py`) запускается без него (`start_launcher … nokeep`).
- Смена языка интерфейса перезагружает страницу: в тестах — `with page.expect_navigation(): page.select_option('#uiLangSel', 'en')`, затем ждать `body[data-model="ready"]`.
- `start_launcher` в `run_all.sh` передаёт программе запуска переменные из `XENV` (так `e2e_v09.py` получает зеркало программы озвучки и голосов).
- Распаковка `.tar.bz2` стандартной библиотекой Go небыстрая (голос 65 МБ — около 10 секунд в облачной среде): тесты ждут окончания скачивания по `/api/state`, а не фиксированное время.
- Без ответа программы запуска на `/api/state` (запасной запуск) у `body` класс `no-tts`: кнопок 🔊 нет.
- Сборка llama.cpp из исходников с `-march=native` не переносится на другой процессор; тесты используют официальный архив выпуска (выбирает вариант под процессор сам).
- Тесты окна приложения ищут процессы программы окна по `/proc/*/exe`, а не `pgrep -f`: по командной строке находится и сама оболочка, запустившая тест.
- Программа окна для Linux — с общей библиотекой C++: статическая (`-static-libstdc++`) потянула бы символы glibc 2.36–2.38 и не запустилась бы на Ubuntu 22.04 и Debian 12; `sscanf` и подобные функции в программе окна не использовать (в glibc 2.38 они стали `__isoc23_*`).
- В Windows программу окна нельзя запускать с флагами скрытого окна (`setChildAttrs`): первое `ShowWindow` взяло бы `SW_HIDE` из параметров запуска.
