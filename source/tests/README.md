# Автоматические тесты

Проверяют программу целиком: настоящую программу запуска, настоящий движок llama.cpp и интерфейс в браузере Chromium. Вместо настоящей модели используется крошечная модель со случайными весами: она отвечает бессмыслицей, но позволяет проверить всю механику. Качество перевода так не проверить — для этого есть кнопка «Тест» на компьютере пользователя (отчёты в `data/reports`).

## Запуск

```
bash source/tests/run_all.sh [рабочая-папка]
```

Работает в Linux (так тесты запускает Claude в своей облачной среде и GitHub Actions). Нужны Go 1.24+, Python 3 с пакетами `playwright` (и его Chromium), `numpy`, `gguf`; один раз нужен доступ к github.com — оттуда скачиваются официальный архив движка, программа озвучки sherpa-onnx для Linux, четыре голоса Piper и `espeak-ng-data` (всё кэшируется в рабочей папке). Для окна приложения (Ubuntu/Debian): `g++ pkg-config libgtk-3-dev libwebkit2gtk-4.1-dev xvfb xdotool imagemagick openbox x11-utils` (в `x11-utils` — `xmessage` для проверки, что окно встаёт впереди), для его сборки под Windows — `g++-mingw-w64-x86-64`; без них эти наборы пропускаются (в сводке — `skip`). Весь прогон занимает несколько минут. В конце печатается сводка; снимки экрана лежат в `<рабочая-папка>/shots`.

## Проверка голосов: `voice_check.py`

Не входит в `run_all.sh`. Тесты выше проверяют, что голос скачивается и программа озвучки его запускает, но не то, *что* он говорит. Испанский голос MLS 9972 (0.9.3) проходил все тесты, а короткие фразы читал выдуманными словами и в 2–5 раз дольше; по образцу на сайте Piper (одно длинное предложение) этого не было слышно. Поэтому перед тем, как голос попадёт в каталог, — проверка распознаванием речи:

```
python3 source/tests/voice_check.py [рабочая-папка] [id голоса …] [--verbose] [--keep] [--voices=файл.json]
```

Каждый голос каталога (каталог берётся из `tts.go` через `go test -run TestDumpVoiceCatalog`) читает восемь фраз своего языка той же программой sherpa-onnx и с теми же параметрами, что программа; Whisper base (sherpa-onnx) распознаёт речь. По шести длинным фразам — секунды речи на знак текста (обычно 0,05–0,07; MLS 9972 — 0,12, отдельные фразы до 0,27) и доля неверных слов (обычно 0–34 %, у китайского — знаков; MLS 9972 — 106–132 %). Вердикт: `ok`, `SLOW` (больше 0,09 с на знак в среднем или 0,16 в одной фразе) или `WORDS` (больше 60 % ошибок); код выхода 1, если не всё `ok`. Две короткие фразы только читаются (Whisper base часто не узнаёт одно слово без контекста) — их можно послушать (`--keep`, WAV в `<рабочая-папка>/speech`). `--voices=файл.json` — проверить голоса из списка в формате каталога (кандидатов, которых ещё нет в `tts.go`). В первый раз скачивает около 1 ГБ с github.com (sherpa-onnx, Whisper base 208 МБ, все голоса каталога; размеры и SHA-256 закреплены), потом 3–4 минуты.

## Правила

- Новая функция — новые проверки в новом файле `e2e_vX.py` / `prompts_vX.py` и строка в `run_all.sh`.
- Тексты, которые тест подставляет вместо ответа модели, — это заготовки теста, а не ответы модели; так и помечено в файлах.
- Тест не должен зависеть от скорости: ждать появления элементов, а не фиксированное время, где это возможно.
- Тесты, которым нужны прежние языки по умолчанию («Авто»), открывают окно как «не новое» (`tdoc.window` и `tdoc.welcome` в `sessionStorage`, см. `e2e_v02.py`): без окна приветствия.
