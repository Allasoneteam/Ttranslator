## Вопросы
1. **Та же схема, что на компьютере?** Программа запуска на Go (сборка для arm64: `GOOS=android` или статически `linux`), движок llama.cpp (`llama-server`) и тот же `ui/index.html` в WebView через 127.0.0.1. Есть ли официальная сборка llama.cpp b11435 для Android? Если нет — сборка из исходников того же выпуска компилятором NDK в CI. Можно ли на Android 10 и новее запускать такие программы (например, из `nativeLibraryDir` под именем `lib….so`)? Что с работой в фоне, памятью, правами?
2. **Если нет** — другая схема (движок внутри приложения через JNI, программа запуска как библиотека): что пришлось бы переписать.
3. **Интерфейс в WebView**: работает ли `index.html` без правок? Окно «Сохранить», импорт и экспорт файлов, буфер обмена, внешние ссылки, шрифты (китайский), размер экрана телефона.
4. **Модели**: модели каталога — от 3,35 ГБ. Хватит ли памяти телефона с 8 ГБ, какой скорости ждать (по открытым замерам llama.cpp на телефонах — со ссылками), где хранить файлы, как скачивать (2–5 ГБ).
5. **Чтение вслух**: sherpa-onnx для Android — те же голоса Piper?
6. **Сборка**: Android SDK, NDK и Gradle в GitHub Actions (шаг `android` в `ci.yml` уже запускает `android/ci.sh <out-dir>`; всё, что положишь в `<out-dir>`, станет артефактом). APK — с отладочной подписью, для установки вручную.
7. **Проверка в CI**: эмулятор (у Linux-машин GitHub есть аппаратное ускорение для него) с маленькой тестовой моделью (`source/tests/make_tiny_gguf.py`): приложение запускается, `/api/state` отвечает, перевод проходит через движок, снимок экрана WebView — в результаты.
8. **iPadOS** — кратко, без прототипа (у автора iPad с M3): что мешает (запускать отдельные программы там нельзя), что понадобится (Xcode, учётная запись Apple, движок внутри приложения), объём работы по сравнению с Android.

## Разрешено для пробы
Согласие автора от 01.11.2026 на пробный APK: стандартные инструменты Android — Android SDK и NDK, Gradle и Android Gradle Plugin, Kotlin или Java — только в папке `android/` и только для пробы. Любые другие библиотеки и сервисы — только описать в отчёте как варианты, не добавлять.
