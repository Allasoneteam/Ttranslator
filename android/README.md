# Ttranslator для Android: можно ли и как

Отчёт облачной сессии Claude по заданию `.claude/tasks/android-feasibility.md` (выдано 01.11.2026), ноябрь 2026.
Здесь же — пробное приложение: папка `android/` (всё новое; `source/` и `ui/` не менялись).

## Коротко

- **Можно — по той же схеме, что на компьютере.** На Android работает та же программа запуска на Go (исходники
  `source/launcher` без единой правки, только собраны для Android), тот же движок llama.cpp b11435 (у него есть
  официальная сборка для Android) и тот же `ui/index.html` без правок — в окне WebView вместо окна браузера.
  Программы лежат внутри APK под именами `lib….so` и запускаются из папки библиотек приложения: так Android 10 и
  новее разрешает запускать программы (из своих папок с данными — уже нельзя).
- **Проверено в CI на эмуляторе Android** (Android 16 и Android 10): приложение запускается, программа запуска
  отвечает (`/api/state`), перевод проходит через движок — и запросом, и в самой странице; чтение вслух работает
  (голос скачан программой запуска с GitHub прямо в эмуляторе). На Android 16 с 8 ГБ памяти приложение само
  скачало **настоящую Gemma 4 E2B · Q4_0** (3,35 ГБ) с Hugging Face, загрузило её и перевело: «The weather is
  nice today…» → «Погода сегодня хорошая, поэтому мы пойдем погуляем в парке.» Снимки экрана — в результатах
  запуска CI. Подробно — раздел 7.
- **Память.** Для телефона с 8 ГБ подходит основная модель каталога — **Gemma 4 E2B · Q4_0**: движок
  llama.cpp b11435 с ней занимает около 2,6 ГБ (мой замер на настоящей модели, раздел 4). E4B · Q4_0 — на грани
  (≈3,5 ГБ), модели Q8_0 для 8 ГБ не годятся.
- **Скорость.** По открытым замерам llama.cpp на телефонах модели 3B пишут примерно 7–15 токенов в секунду на
  средних телефонах и флагманах 2022–2023 годов; E2B должна быть быстрее. Вариант перевода фразы — порядка
  5–15 секунд. Точно покажет «Быстрый тест» на телефоне автора.
- **Что придётся доделать для настоящего приложения:** вид интерфейса на узком экране телефона (шапка сейчас
  шире экрана, кнопку «Перевести» обрезает граница панели — правки `index.html`, список в разделе 3), работа в
  фоне во время перевода и скачивания,
  закрыть доступ к программе запуска другим приложениям телефона, мелочи Android. Оценка — раздел «Объём работы»:
  около двух недель работы Claude плюс проверки автора на телефоне.
- **Нужен свежий «Android System WebView»** (версия 80+; на телефонах с Google Play он обновляется сам) — со
  старым скрипт страницы не работает; приложение тогда просит обновить WebView.
- **Нужны решения автора** — в конце (главное: класть ли программу озвучки в APK; где хранить модели).

## Ответы на вопросы задания

### 1. Та же схема, что на компьютере?

**Да.** Окно (WebView) ⇄ программа запуска (Go, 127.0.0.1:8765) ⇄ движок `llama-server` (127.0.0.1, случайный порт),
как в `source/docs/ARCHITECTURE.md`. Что для этого понадобилось:

- **Программа запуска** собирается `GOOS=android` для arm64 (телефоны) и x86_64 (эмулятор). Обязательно с cgo
  (компилятор NDK): без него на Android не работает DNS — собственный резолвер Go читает `/etc/resolv.conf`,
  которого на Android нет (в исходниках Go так и написано: «DNS requests don't work on Android, so prefer the cgo
  resolver»). С cgo имена разрешает сам Android; сертификаты для HTTPS Go на Android берёт из системных
  (`/system/etc/security/cacerts`; с Android 14 обновляемые сертификаты лежат ещё в модуле Conscrypt — обёртка
  передаёт программе запуска обе папки через стандартную переменную Go `SSL_CERT_DIR`). Это по-прежнему только
  стандартная библиотека Go — cgo нужен ей самой.
  Код программы запуска не менялся: на Android она — та же Linux-версия (`sys_linux.go`).
- **Движок: официальная сборка есть.** В выпуске llama.cpp b11435 — архив `llama-b11435-bin-android-arm64.tar.gz`
  (73 924 873 байта, SHA-256 `7b4788…efdefe`; собран NDK r29 для Android 9+). В нём `llama-server` с библиотеками
  и семь вариантов вычислительной части под разные процессоры телефонов (от ARMv8.0 до ARMv9.2 с dotprod, i8mm,
  SVE, SME) — движок сам выбирает лучший при запуске. Сборки для x86_64 Android в выпуске нет — для эмулятора
  `android/build.sh` собирает тот же выпуск из исходников компилятором NDK (в APK для телефона попадает
  официальная сборка). В архиве файлы с отладочной информацией (≈250 МБ); `build.sh` её убирает (≈27 МБ).
- **Можно ли запускать программы на Android 10 и новее? Да, но только из APK.** С Android 10 (targetSdk 29+)
  приложению запрещено запускать (`execve`) и подключать (`dlopen`) код из своих записываемых папок — это правило
  SELinux ([изменение в AOSP](https://android.googlesource.com/platform/system/sepolicy/+/b362474374afc402f65695252d30a008326c0eba%5E%21/),
  [поведение Android 10](https://developer.android.com/about/versions/10/behavior-changes-10#execute-permission):
  «Apps should load only the binary code that's embedded within an app's APK file»). Разрешено — запускать файлы из
  папки библиотек приложения (`nativeLibraryDir`): туда Android сам распаковывает файлы `lib<имя>.so` из APK, если в
  APK указано `extractNativeLibs="true"`. Так работают Termux-пакеты и другие приложения
  ([Termux и Android 10](https://github.com/termux/termux-packages/wiki/Termux-and-Android-10)). В пробе так
  запускаются все три программы: `libttranslator.so` (программа запуска), `libllama-server.so` (движок),
  `libsherpa-onnx-offline-tts.so` (чтение вслух). Проверено в эмуляторе Android 10 и 16.
  - Следствие: **скачать движок или программу озвучки и запустить** (как на компьютере) **на Android нельзя** —
    всё исполняемое должно быть внутри APK. Скачиваются только данные: модели и голоса.
- **Работа в фоне.** Дочерние программы приложения Android 12+ называет «фантомными процессами» и следит за ними:
  не больше 32 на все приложения сразу и снятие тех, кто в фоне долго нагружает процессор
  ([разбор](https://github.com/agnostic-apollo/Android-Docs/blob/master/en/docs/apps/processes/phantom-cached-and-empty-processes.md)).
  У Ttranslator их 2–3. В пробе проверено: после 30 секунд в фоне программа запуска отвечает, модель загружена,
  страница при возвращении та же (текст не пропал). Но долгий перевод или скачивание в фоне Android может
  прервать. В настоящем приложении на это время нужна «служба переднего плана» — уведомление «Ttranslator
  переводит / скачивает модель» (с Android 15 у служб типа `dataSync` лимит 6 часов в сутки,
  [документация](https://developer.android.com/develop/background-work/services/fg-service-timeout)).
- **Когда Android закрывает приложение** (нехватка памяти, смахнули из списка, «Остановить»), программа запуска и
  движок закрываются вместе с ним — проверено в эмуляторе. Висящих процессов не остаётся.
- **Права:** только `INTERNET` (он нужен и для 127.0.0.1). Разрешений на файлы не нужно: папка программы —
  папка приложения на общей памяти телефона, `Android/data/io.github.allasoneteam.ttranslator/files` (раздел 4).

### 2. Если бы запускать программы было нельзя: другая схема

Сейчас не нужна, но это запасной путь, если Google когда-нибудь закроет и запуск из папки библиотек:

- Движок — библиотекой внутри приложения: в b11435 `llama-server` уже разделён на крошечную программу (7 КБ) и
  библиотеку `libllama-server-impl.so` с функциями `llama_server(argc, argv)` и `llama_server_terminate()`. Их можно
  вызвать из приложения (JNI) в отдельном потоке — сервер на 127.0.0.1 тот же, интерфейс и программа запуска не
  меняются. Чтобы «Выгрузить модель» действительно освобождало память, движок лучше держать в отдельном процессе
  приложения (`android:process=":engine"` — это разрешено).
- Программа запуска — библиотекой: `go build -buildmode=c-shared` с одной функцией «запустить с папкой X».
  Переписать пришлось бы только запуск и остановку движка и программы озвучки (`startEngine`, `stopEngine`,
  `synthesize`): вместо `exec` — вызовы библиотек.
- Чтение вслух — через официальную JNI-библиотеку sherpa-onnx (есть в выпуске) из приложения.
- Объём: примерно неделя сверх варианта 1.

### 3. Интерфейс в WebView

`index.html` открывается **без правок** — WebView грузит его с программы запуска, как браузер. Проверено в
эмуляторе (снимки экрана — в результатах CI).

**Нужен WebView не старше версии 80** (2020 год): скрипт страницы использует оператор `??`, а со старым WebView
он не запускается вовсе. Так было в эмуляторе Android 10: там стоит исходный WebView 74 (2019). На телефонах
«Android System WebView» обновляется через Google Play сам (сейчас версии 13x); если он всё же старый, приложение
не показывает сломанную страницу, а просит обновить WebView и даёт кнопку «Открыть Google Play» (проверено в
эмуляторе Android 10). По пунктам задания:

| Что | На Android | В пробе |
|---|---|---|
| Окно «Сохранить» (экспорт словаря и «Сохранённых») | страница уже умеет сохранять через функцию окна `ttwSaveFile` (так работает `ttranslator-window`) | приложение даёт странице те же функции окна (`ttwSaveFile`, `ttwOpenExternal`, `ttwClose`) — до её скриптов, как `ttranslator-window`. «Сохранить» открывает системный выбор места (папка «Загрузки», Google Диск…) |
| Импорт файлов | `<input type=file>` в WebView работает, только если приложение покажет выбор файла | сделано: системный выбор файла |
| Буфер обмена | `navigator.clipboard` есть: страница открыта с 127.0.0.1 — «безопасный адрес»; запасной путь `execCommand('copy')` в странице уже есть | в эмуляторе Android 16 кнопка «Копировать» положила текст варианта в буфер обмена Android (система показала его в своём окошке) |
| Внешние ссылки | через `ttwOpenExternal` — в браузере или почтовой программе телефона | сделано |
| Шрифты (китайский) | у Android есть шрифт Noto Sans CJK; в списке шрифтов `index.html` для `zh` он есть | китайский интерфейс в эмуляторе отображается правильно (снимок `6-chinese.png`) |
| Размер экрана | страница уже переходит в одну колонку уже 760 точек; телефон ≈ 412 точек | работать можно, но шапка и кнопка «Перевести» не помещаются — что поправить, ниже |
| Чтение вслух | `<audio>` в WebView работает; приложение разрешает звук без нажатия (следующие фразы) | проверено в эмуляторе |
| Выход | «Выход» → программа запуска закрывается, окно — `ttwClose` | проверено |

**Что придётся поправить в `index.html`** (не трогал: его сейчас меняет сессия macOS) — для настоящего приложения:

1. Узкий экран (снимки CI: ширина страницы на телефоне — 412 точек): кнопки шапки уходят за правый край
   («Тест», «?», «О программе», «Выход» не видны); кнопку «Перевести» обрезает граница верхней панели (видна
   только её верхняя кромка); заголовки карточек вариантов переносятся в узкий столбик; подсказки по наведению
   мыши (`title`) на телефоне не видны. Из-за широкой шапки рабочее окно получается шире экрана (527 точек вместо
   412), и WebView уменьшает всю страницу — текст мельче, чем мог бы быть. Окно приветствия, экран первого
   запуска и карточки вариантов в целом читаются хорошо. Нужен вариант раскладки для ширины ~360–420 точек:
   кнопки шапки — в меню «⋮», панель ввода — по высоте содержимого.
2. «Открыть папку» (данные, журналы, словари, сохранённые): на Android программа запуска не может открыть папку
   (нет Проводника) — кнопки показывают ошибку. Скрыть их на Android или показывать путь
   (`Android/data/…/files`).
3. «Вид окна» (окно приложения / вкладка браузера) в «Настройках» и окне приветствия на Android не имеет смысла —
   скрыть.
4. «Скачать отчёт» в окне «Теста» — ссылка-скачивание, в WebView она не работает (отчёт при этом сохраняется в
   `data/reports`); в своём окне — через `ttwSaveFile`, как экспорт.
5. Подсказки «Ctrl+Enter» и тексты про Windows/Linux (WebView2, WebKitGTK) — на телефоне лишние.

**В программе запуска** (`source/launcher`) для настоящего приложения — небольшие правки (в пробе их нет):
- путь к движку обёртка сейчас записывает в `config.json` (`engine_path`) при каждом запуске — лучше отдельная
  настройка для Android (переменная окружения), чтобы не трогать настройку пользователя;
- **защита**: на телефоне к 127.0.0.1:8765 может подключиться любое другое приложение; запросы страницы с другого
  сайта программа запуска уже отклоняет, а запросы чтения (`GET /api/saved` …) — нет. Нужен случайный ключ, как у
  движка: обёртка передаёт его программе запуска и странице;
- «Открыть папку» на Android — ответить понятной ошибкой;
- число потоков движка по умолчанию — см. раздел 4 (в пробе его ставит обёртка).

### 4. Модели: память, скорость, где хранить, как скачивать

**Память.** Замер: llama.cpp b11435 (та же версия), настоящие модели каталога, контекст 4096 — как их запускает
программа запуска (Linux x86_64 в облаке; на ARM устройство памяти то же). «Нужно движку» — его собственная оценка
при загрузке.

| Модель (файл) | Нужно движку | Из чего складывается |
|---|---|---|
| Gemma 4 E2B · Q4_0 (3,35 ГБ) | **≈ 2,6 ГБ** | веса из файла (отображаются в память, читаются по мере надобности) + 1,0 ГБ весов, переупакованных для быстрых команд процессора; память контекста — 36 МБ |
| Gemma 4 E4B · Q4_0 (5,15 ГБ) | ≈ 3,5 ГБ | + 2,1 ГБ переупакованных весов; контекст 104 МБ |
| Gemma 4 E2B · Q8_0 (4,97 ГБ) | ≈ 5,3 ГБ | — |
| Gemma 4 E4B · Q8_0 (8,03 ГБ) | > 8 ГБ (оценка, не мерил) | — |

Почему E2B нужно меньше размера файла: большая таблица «встраиваний по слоям» модели Gemma 4 E читается только для
слов текста, и система держит в памяти лишь нужные её части. Сразу после загрузки движок прочитывает весь файл
(занято ≈4,3 ГБ), но эта часть памяти — копия файла, Android отдаёт её другим при нехватке.

На телефоне с 8 ГБ сам Android и фоновые приложения обычно занимают 3–4 ГБ, приложению остаётся 3,5–5 ГБ. Значит:
**E2B · Q4_0 — подходит** (≈2,6 ГБ + окно WebView ≈0,2–0,3 ГБ); **E4B · Q4_0 — на грани** (может работать, если
ничего больше не открыто; Android будет закрывать другие приложения, возможны замедления); **Q8_0 — нет**.

Проверено и на самом Android: в эмуляторе Android 16 с 8 ГБ памяти приложение скачало E2B · Q4_0, загрузило и
перевело ею (раздел 7). Движок занял там 3,4 ГБ, но почти всё это — отображённый в память файл модели (3,3 ГБ);
собственной памяти движка — 0,14 ГБ, и свободной памяти у системы осталось 6,0 ГБ из 8,1 (до загрузки — 6,1):
Android считает страницы файла свободными — при нехватке он их просто отпустит. На телефоне собственной памяти
будет больше — около 1,1 ГБ: на ARM движок переупаковывает веса Q4_0 под команды процессора (в эмуляторе x86
без AVX2 он этого не делает).

**Скорость** — открытые замеры llama.cpp на процессоре телефонов (генерация — сколько токенов в секунду пишет
модель; токен — часть слова; «промпт» — сколько токенов запроса в секунду модель читает):

| Телефон (процессор) | Модель | Чтение запроса | Генерация | Источник |
|---|---|---|---|---|
| OPPO Reno7 5G (Snapdragon 778G, 8 ГБ) | Qwen2.5-3B Q4_K_M, 4 потока | 29–40 т/с | 7,5 т/с | [набор замеров](https://huggingface.co/datasets/vovaxa44/snapdragon778g-llama-cpp-opencl-bench) |
| OnePlus 11 (Snapdragon 8 Gen 2) | то же | 41–45 т/с | 12,5–13,8 т/с | там же |
| Zenfone 9 (Snapdragon 8+ Gen 1) | Llama 3.2 3B Q4_0, 4 потока | 56 т/с | 15 т/с | [llama.cpp #10662](https://github.com/ggml-org/llama.cpp/issues/10662) (12.2024) |
| Samsung S26 Ultra | Gemma 4 E2B (не llama.cpp, а Google LiteRT-LM), процессор | 557 т/с | 47 т/с | [Google](https://developers.google.com/edge/litert-lm/models/gemma-4) |

- Генерация упирается в скорость памяти: на каждый токен модель прочитывает свои веса. E2B · Q4_0 читает на токен
  примерно вдвое меньше, чем модели 3B из таблицы, поэтому **ожидаю для E2B ≈ 10–14 т/с на среднем телефоне и
  ≈ 20–25 т/с на флагмане 2022–2023 годов**. Вариант перевода фразы (запрос ≈150–300 токенов, ответ ≈30–60) —
  примерно 5–15 секунд, три стиля — втрое дольше. Это оценка; настоящие цифры даст «Быстрый тест» на телефоне.
- **Потоки:** на телефоне 8 ядер, обычно 4 из них маленькие. llama.cpp по умолчанию берёт все 8 — и генерация на
  ~40 % медленнее, чем с 4 потоками (замер на 778G там же). Поэтому обёртка при первом запуске пишет в
  `config.json` число «больших» ядер (`threads`; маленькие ядра она узнаёт по модели ядра в `/proc/cpuinfo`).
- **Видеокарта** телефона пока не помогает: в замерах llama.cpp OpenCL на Adreno медленнее процессора при любом
  числе слоёв; у Google (LiteRT) видеокарта ускоряет чтение запроса в 6–7 раз, а генерацию — лишь на 10–20 %.
  На будущее — проверить OpenCL-сборку llama.cpp для Snapdragon (она есть в выпуске) и NPU.
- Телефон греется и сбрасывает частоту: в том же замере чтение запроса на горячем телефоне на 29 % медленнее.

**Где хранить файлы.** Папка программы в пробе — `Android/data/io.github.allasoneteam.ttranslator/files` на общей
памяти телефона (внутри — как на компьютере: `config.json`, `data/`, `models/`, `engine/`):
- разрешения не нужны; программа запуска сама скачивает туда модели и голоса, и сама видит `.gguf`, положенные
  в `models/`;
- **скопировать модель с компьютера** (из папки `models` программы на компьютере) по кабелю USB в
  `Android/data/…/files/models` — на Android 10 получается; на новых Android в чужие папки `Android/data` часто
  можно только смотреть, но не писать (в эмуляторе Android 16 не смогла записать даже отладочная программа adb).
  Поэтому в пробе основной путь — скачивание в самом приложении, а для настоящего приложения я предлагаю
  «импорт модели»: файл `.gguf` в «Загрузках» телефона → «Поделиться» → Ttranslator, приложение копирует его к
  себе (это ему разрешено всегда);
- в Android 11+ файловые менеджеры телефона в `Android/data` не заглядывают;
- при удалении приложения папка удаляется; в пробе включено `hasFragileUserData` — Android 10+ при удалении
  спрашивает, оставить ли данные приложения (модели).
- Другой вариант — папка, которую выберет пользователь (например, `Download/Ttranslator`): видна любому файловому
  менеджеру, но нужно отдельное разрешение или выбор папки через систему — сложнее. Решение автора (ниже).

**Как скачивать 2–5 ГБ.** Программа запуска скачивает сама, как на компьютере: с докачкой после обрыва, с
проверкой размера и SHA-256, с тем же окном подтверждения (откуда, куда, какой файл). В эмуляторе Android 16 она
так скачала E2B · Q4_0 (3,35 ГБ) с Hugging Face — 8–19 МБ/с (в разных запусках), 4–8 минут вместе с проверкой и
загрузкой; голос (67 МБ) с GitHub — за 12–18 секунд. Значит, DNS и HTTPS программы на Go на Android работают. На
телефоне — лучше по Wi-Fi и с включённым экраном:
пока приложение в фоне, Android может прервать скачивание (тогда «Повторить» продолжит с того же места). В
настоящем приложении — уведомление-служба на время скачивания.

### 5. Чтение вслух: sherpa-onnx на Android — те же голоса Piper?

**Да, те же голоса**: голос — это файлы модели ONNX, `tokens.txt` и `espeak-ng-data` (или словарь у китайского),
одинаковые для всех систем; программа запуска скачивает их из того же выпуска `tts-models` sherpa-onnx.

Но **готовой программы `sherpa-onnx-offline-tts` для Android в выпуске нет**: в `sherpa-onnx-v1.13.7-android.tar.bz2`
(45 287 000 байт, SHA-256 `7208b2…622e6e`) только библиотеки для приложений (JNI и C API) и `libonnxruntime.so`. В
пробе — маленькая программа на C (`android/native/tts-cli.c`, ~100 строк): принимает те же параметры, что
`sherpa-onnx-offline-tts` (как их передаёт `tts.go`), и вызывает официальную библиотеку. Программа запуска при
этом не меняется. Проверено: на Linux тот же голос этой программой и официальной читает фразу одинаково (2,6 с
речи у обеих; у голосов Piper длина чуть меняется от раза к разу), китайский голос со словарём и правилами — тоже;
в эмуляторе Android — голос en LJSpeech скачан программой запуска и читает (запись `tts-en.wav` — в результатах CI).

Важно для решения автора: на компьютере sherpa-onnx в архив не кладётся, а скачивается при первом голосе (решение
от 21.10.2026). На Android так нельзя (раздел 1: скачанный код не запустить) — программа озвучки должна лежать в
APK (+26 МБ к APK для телефона). В её библиотеке — espeak-ng под лицензией GPL-3.0: распространять APK с ней можно,
но с указанием лицензии и ссылкой на исходники (в пробе — `assets/THIRD-PARTY.txt` в APK).

### 6. Сборка

`android/build.sh` (его вызывает `android/ci.sh` в шаге `android` CI) — всё из официальных источников, версии
закреплены, размер и SHA-256 проверяются (у исходников llama.cpp — коммит):

- Android SDK (на машинах GitHub он уже есть), NDK r29 (как у официальной сборки llama.cpp), Gradle 9.8.2,
  Android Gradle Plugin 9.5.0; приложение на Java только с Android SDK — **без сторонних библиотек** (даже
  стандартную библиотеку Kotlin, которую AGP 9 добавляет сам, я отключил);
- программа запуска — Go с NDK; движок — официальный архив (arm64) и сборка того же выпуска (x86_64, для
  эмулятора, ≈4 минуты); программа озвучки — официальные библиотеки + `tts-cli.c`;
- APK с отладочной подписью: ключ лежит в репозитории (`android/app/debug.keystore`, «Android Debug», пароль
  `android`) — каждый пробный APK подписан одним ключом, поэтому новый ставится поверх старого и скачанные
  модели остаются. Для публикации нужен будет свой ключ (решение автора).
- Размер: APK ≈ 50 МБ (в нём программы для телефона и для эмулятора); на телефоне после установки ≈ 60 МБ
  программ. Только для телефонов — было бы ≈ 26 МБ.

### 8. iPadOS (кратко, без прототипа)

- **Главное препятствие:** приложениям iPadOS нельзя запускать отдельные программы (нет `fork`/`exec`,
  [Apple Developer Forums](https://developer.apple.com/forums/thread/747499)) и загружать скачанный код. Значит,
  схема 1 (программа запуска + отдельный движок) невозможна; только «всё внутри приложения», как схема 2:
  - движок — библиотекой: у llama.cpp b11435 есть официальная сборка для iOS/iPadOS
    (`llama-b11435-xcframework.zip`), на M3 — с ускорением Metal (видеокарта); сервер llama.cpp (`llama-server`)
    в неё не входит — его исходники пришлось бы собирать в приложение или обращаться к библиотеке напрямую;
  - программа запуска — Go как библиотека (`-buildmode=c-archive` для iOS, нужен Xcode); всё, что в ней запускает
    процессы (движок, озвучку), — переписать на вызовы библиотек;
  - окно — WKWebView со страницей (тот же `index.html`), функции окна — как на macOS (сессия macOS делает часть
    Cocoa для окна; на iPadOS — UIKit);
  - чтение вслух — sherpa-onnx собирается для iOS из исходников (готового архива в выпуске v1.13.7 нет).
- **Нужно:** Mac с Xcode (в CI — машины macOS у GitHub), учётная запись Apple: бесплатная позволяет поставить
  приложение на свой iPad из Xcode на 7 дней; платная (99 $ в год) — TestFlight и App Store. Памяти: iPadOS даёт
  приложению лишь часть памяти iPad, больше — с особым разрешением `increased-memory-limit`
  ([Apple](https://developer.apple.com/tutorials/data/documentation/bundleresources/entitlements/com.apple.developer.kernel.increased-memory-limit.md);
  для iPad с 8 ГБ сообщали о пределе до ~6 ГБ с ним). E2B · Q4_0 (≈2,6 ГБ) на iPad M3 должна помещаться и
  работать быстрее, чем на телефоне (Metal).
- **Объём:** заметно больше, чем Android, — примерно в 2–3 раза: на Android программа запуска и движок остаются
  как есть, на iPadOS их часть переписывается, плюс подпись и распространение через Apple.

## Что в пробе работает и что нет

Работает (проверено в эмуляторе, раздел 7): запуск программ из папки библиотек; выбор модели и загрузка;
скачивание модели (3,35 ГБ с Hugging Face) и голоса (с GitHub) самим приложением; перевод запросом и в странице —
и маленькой, и настоящей моделью; китайский интерфейс; чтение вслух; работа в фоне; закрытие приложения
системой; «Выход»; просьба обновить слишком старый WebView. Android 16 — всё, Android 10 — основное (страница —
только с обновлённым WebView).

Сделано, но в эмуляторе не проверено (проверит автор на телефоне): окно «Сохранить» (экспорт) и выбор файла для
импорта — они открывают системные окна, которыми проверка не управляет; внешние ссылки; поворот экрана и
клавиатура; работа на настоящем телефоне ARM (в эмуляторе — x86_64; официальная сборка движка для ARM в нём не
запускается, её проверит телефон автора).

Не сделано (для настоящего приложения): раскладка интерфейса для телефона и прочие правки `index.html`
(раздел 3); служба переднего плана на время перевода и скачивания; ключ доступа к программе запуска; импорт модели
через «Поделиться»; кнопка «Назад» закрывает только приложение целиком (не панели страницы); подписанный выпуск.

## Рекомендуемая схема

Та, что в пробе: **APK = окно WebView на Java + те же программы, что на компьютере** (программа запуска на Go,
официальный `llama-server` для Android, программа озвучки на официальных библиотеках sherpa-onnx), запуск из
папки библиотек приложения; модели и голоса — скачивает программа запуска (в настоящем приложении — ещё импорт
файла модели через «Поделиться»).
Почему: один код программы запуска и один `index.html` на все системы; движок — официальный выпуск (обновляется
так же, как на компьютере, — сменой номера выпуска); минимум кода только для Android (≈850 строк Java и 100 строк
C). Запасной путь, если Google закроет запуск из папки библиотек, — схема 2 (раздел 2).

## Объём работы по этапам (оценка)

1. **Интерфейс для телефона** (`index.html`): раскладка узкого экрана, скрыть «Вид окна» и «Открыть папку»,
   «Скачать отчёт» через функцию окна, сенсорные мелочи — 3–5 дней; проверка автора на телефоне.
2. **Программа запуска для Android** (`source/launcher`, маленькие правки): ключ доступа, путь к движку без
   `config.json`, ответ на «Открыть папку», потоки — 1–2 дня; все наборы `run_all.sh` не меняются.
3. **Приложение**: служба переднего плана на время перевода и скачивания (уведомление), импорт модели через
   «Поделиться», «Назад» закрывает панели, поворот и клавиатура, тёмная тема системных полос, свой ключ подписи,
   номер версии, APK только для телефонов (без x86_64 — вдвое меньше) — 3–4 дня.
4. **Выпуск**: APK в архивах выпуска (CI уже собирает), инструкция по установке в README на пяти языках,
   проверка на 2–3 телефонах (автор) — 2 дня.

Итого ≈ 2 недели работы Claude плюс проверки автора; CI-проверка в эмуляторе уже есть и будет расти вместе с
приложением.
5. Потом, по желанию: ускорение на видеокарте или NPU (OpenCL-сборка llama.cpp для Snapdragon), Google Play.

## Риски

- Google может со временем ограничить запуск программ и из папки библиотек (Termux живёт на этом много лет,
  но гарантий нет) — тогда схема 2 (≈ неделя).
- Android прерывает фоновые программы: без службы переднего плана долгий перевод или скачивание в фоне могут
  оборваться; производители (Xiaomi, Samsung…) делают это жёстче.
- Память: E4B на 8 ГБ — на грани; при нехватке Android закрывает приложение целиком (модель грузится заново).
- Скорость и нагрев: на средних телефонах перевод заметно медленнее компьютера; долгий «Подробный тест» нагреет
  телефон.
- Другие приложения телефона могут обращаться к 127.0.0.1:8765, пока не добавлен ключ доступа (этап 2).
- espeak-ng (GPL-3.0) внутри APK, если оставить чтение вслух.
- Регистрация разработчиков у Google для любых APK (с 2027 года во всех странах, см. «Решения автора», п. 5):
  без неё установка станет сложнее.
- Проверено только в эмуляторе x86_64; на настоящем телефоне ARM могут найтись свои особенности — для этого
  пробный APK.

## Нужны решения автора

1. **Чтение вслух на Android:** класть программу озвучки sherpa-onnx в APK (+26 МБ; espeak-ng под GPL-3.0
   внутри; скачать её «по требованию», как на компьютере, Android не позволяет) — как в пробе; или Android-версия
   без чтения вслух.
2. **Где хранить модели:** папка приложения `Android/data/…` (как в пробе: без разрешений; с компьютера видна, но
   на новых Android писать в неё с компьютера часто нельзя; удаляется вместе с приложением, если не оставить
   данные) плюс «импорт модели» через «Поделиться» (предложение) — или папка на выбор пользователя (видна в
   файловом менеджере телефона, но сложнее).
3. **Каталог моделей на телефоне:** показывать все четыре Gemma 4 или на телефонах с 8 ГБ — только E2B · Q4_0
   (остальные — с предупреждением о памяти).
4. **Язык при первом запуске:** как на компьютере — английский с выбором на первом экране (так в пробе), или язык
   телефона, если он из пяти.
5. **Распространение:** только APK в выпусках GitHub (установка «из неизвестных источников») или ещё Google Play
   (учётная запись разработчика 25 $ один раз, проверка Google, свой ключ подписи). Учтите: Google вводит
   обязательную регистрацию разработчиков и для APK, которые ставят не из Google Play: с 30.09.2026 — в Бразилии,
   Индонезии, Сингапуре и Таиланде, в 2027 году — во всех странах
   ([Google](https://android-developers.googleblog.com/2026/03/android-developer-verification.html),
   [справка](https://support.google.com/android-developer-console/answer/16561738?hl=en)). Варианты: бесплатная
   учётная запись «для своих» (без документов, только почта, до 20 устройств) или обычная (25 $ и проверка
   личности; имя разработчика видно). Без регистрации APK на сертифицированных телефонах ставится только
   «продвинутым» способом (лишние шаги) или с компьютера через ADB. Пробный APK это пока не затрагивает.
6. **Когда:** по решению автора само приложение — после выпуска 1.1.

## Как поставить пробный APK на телефон

1. На компьютере откройте [последний запуск CI ветки](https://github.com/Allasoneteam/Ttranslator/actions?query=branch%3Aclaude%2Fandroid-feasibility)
   (войдя в GitHub), внизу страницы «Artifacts» — **android-results**, скачайте и распакуйте zip. Внутри — файл
   `Ttranslator-1.0-android-test.apk` (и `.sha256`). Артефакты хранятся 14 дней; новый запуск CI делает новый APK.
2. Перенесите APK на телефон (кабель USB, почта самому себе, облачный диск — как удобнее).
3. На телефоне откройте APK в «Файлах» (или в «Загрузках»). Android спросит разрешение на установку из этого
   источника: «Настройки» → разрешить «Установку неизвестных приложений» для «Файлов» (или браузера) → назад →
   «Установить». Google Play Защита может предупредить о неизвестном разработчике — «Всё равно установить».
4. Откройте Ttranslator. Первый экран — как на компьютере: выберите язык, затем «Скачать» — скачается модель
   Gemma 4 E2B · Q4_0 (3,35 ГБ; лучше по Wi-Fi, экран не выключать, приложение не сворачивать).
   Можно попробовать вместо скачивания скопировать уже скачанный файл с компьютера: подключите телефон кабелем
   (режим «Передача файлов»), на компьютере откройте «Внутренняя память → Android → data →
   io.github.allasoneteam.ttranslator → files → models» (папка появляется после первого запуска приложения) и
   положите туда `gemma-4-E2B_q4_0-it.gguf` из папки `models` программы на компьютере; затем в приложении — меню
   моделей. На новых Android эта папка может быть закрыта для записи — тогда просто скачайте модель в приложении.
5. Новый пробный APK ставится поверх старого так же (модели и настройки остаются). Удалить — как любое
   приложение (Android предложит оставить данные — модели).

## Что проверить на телефоне

1. Модель телефона и Android (Настройки → О телефоне) — напишите их, пожалуйста: от процессора зависит скорость.
2. «Тест» → **«Быстрый тест»**: скорость (токенов в секунду) и время; отчёт — в `data/reports` (по USB:
   `Android/data/…/files/data/reports`).
3. Обычный перевод абзаца, «Спросить модель», «Случайно»: сколько секунд до первого слова и до конца.
4. Работа в фоне: начать перевод, свернуть приложение на минуту, вернуться — перевод закончен или оборвался?
5. Чтение вслух: скачать голос (меню моделей), 🔊 у текста и у варианта.
6. Сохранить словарь или «Сохранённые» в файл (откроется окно выбора места) и импортировать файл обратно.
7. Поворот экрана, клавиатура (не закрывает ли поле), китайский интерфейс.
8. Если что-то не так — пришлите `data/logs` (`launcher.log`, `engine.log`, `android.log`; по USB:
   `Android/data/…/files/data/logs`) и снимок экрана.

## Устройство папки `android/` (для разработчиков)

```
android/
  README.md            этот отчёт
  build.sh             сборка APK (версии, размеры, SHA-256 всего скачиваемого — в начале файла)
  ci.sh                шаг android CI: build.sh + эмуляторы + проверка
  test/emulator_test.py  проверка в эмуляторе (adb, протокол отладки WebView)
  native/tts-cli.c     программа чтения вслух над C API sherpa-onnx (те же параметры, что sherpa-onnx-offline-tts)
  THIRD-PARTY.txt      лицензии программ в APK (в APK — assets/)
  settings.gradle, build.gradle, gradle.properties, app/build.gradle   проект Gradle (только Android Gradle Plugin)
  app/debug.keystore   открытый тестовый ключ подписи (не для публикации)
  app/src/main/        AndroidManifest.xml, java/…/{MainActivity,Launcher,Texts}.java, res/
```

- `Launcher.java`: папка программы (`TDOC_ROOT` = `getExternalFilesDir`), `config.json` (`engine_path` — к
  `libllama-server.so` в папке библиотек; у нового — `ui_language: en` и `threads`), `engine/android-<arch>/tts.json`
  (путь к программе озвучки — относительный, как его читает `tts.go`), запуск `libttranslator.so --no-window`,
  журнал `data/logs/android.log`.
- `MainActivity.java`: WebView со страницей `http://127.0.0.1:8765/`; в ответ на запрос страницы приложение
  вставляет функции окна до её скриптов (как `ttranslator-window`); выбор файла, «Сохранить как», внешние ссылки,
  отступы под системные полосы и клавиатуру, перезапуск программы запуска после долгого перерыва.
- Сборка у себя: `ANDROID_HOME=<sdk> bash android/build.sh` (нужны JDK 17+, Go 1.24+, cmake, git; ≈10 минут);
  проверка: `bash android/ci.sh <папка>` на Linux с `/dev/kvm`.
